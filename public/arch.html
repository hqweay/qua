一、分层：单向依赖，由内向外arch-check [13] 硬断言，不设白名单例外
host
electron/ · main.ts ＋ library/（sqlite／session／registry／assets／windows） 窗口 · 库会话 · SQLite · fs · 路径 · 菜单。准入是白名单（arch [2+]）：只许 node:*／electron／core/msg／core/library ＋ core 的类型；块语义、查询、渲染一律不许。IPC 按 sender.id 路由，渲染层不告诉主进程「我是哪个库」
app
src/app/ · handlers/ · wiring/ 命令实现与装配。handler 不得碰 DOM（arch [18]），要焦点/滚动/剪贴板一律走 App 门面
ui
src/ui/ · 槽 / 面板 / 弹层 / 周边编辑器 堆叠归槽、tab 归块；槽的清单里只有位置（块 id ／ cmd: 小卡 ／ 宿主现算的派生卡），没有「页面列表组件」这类实体化容器。组件块的两个露面：槽里一张卡、正文一行只读摘要
view
src/view/ · block-dom · editor · editor-events · dom-text · icons · dnd（拖拽的载荷与落点） view 不得 import ui（这条被断言拦下来过）。块 DOM 契约在这里诞生：data-block-id / data-depth / .marker / .left / .tx
core
src/core/ · {{CORE_MODULES}} 个模块 零 DOM。模型 / 行内内容 / 树 / 查询 / 命令声明 / 绑定表 / 上下文键 / 持久化全在这层，可直接在 Node 里单测
依赖只能向下（外→内）inner 不知道 outer 的存在
二、数据结构：一片森林，行内内容是块上的一串 run落盘形状见 src/core/storage/shape.ts · 类型见 src/core/runs.ts
Block { id: string 32-hex UUIDv7 content: Run[] 行内内容＝run 序列；空块＝[] children: Block[] 子树；整库是一片森林，没有「页实体」 created: number 出生时刻（墙钟毫秒）。必填：不可能缺席，所以不是属性槽 modified: number 最后一次改动（只在编辑边界更新，并进内容那条 upsert） annos?: Anno[] 可引用区间：只在被引用时才存在（不写空数组） props?: { 属性袋：键＝定义块的 id，不是名字 _type? 封闭注册表：core/outline · core/divider · core/collection-widget _icon? lucide:<name> 或字面文本 _date? 有它 ⇒ 日记块（只读、全局一天一个） _aliases? 地址：0..N，首个是主名，全局唯一 _lists? 露面：page / tag，可兼位、可空 _display? 这一行显示别名还是正文 _tags? 分类归属：存标签块的 id（有序） _belongsTo? 归属（filed-under）：子块 → 上级，任何块都能配、可多父 _deletedAt? 有它 ⇒ 这块被软删了（子树不可见是继承来的） _kind? 有它 ⇒ 属性定义块（种类是它自己的数据） _query? 有它 ⇒ 查询视图块（值是 where 条件） _queryResult? 冻结的查询结果（成员与顺序；只在刷新时改） _mounts? 块底挂载区的用户栏：{ label, spec }[]（tab 是一格数据，不是块） _items? 集合组件的引用列表：块 id[]（有序引用，不是 children —— 零级联） _ownProps? · _fieldDefs? · _choices? · _uiPosition? [定义块 id]: unknown 用户/插件定义的字段值 } } Doc = { roots: Block[], folded?: Record<id, true> } 折叠态在 Doc 上，不在块上 Workspace = { version: {{WORKSPACE_VERSION}}, blocks: Block[], activeId: string, savedAt: number } 行内内容与区间都住在块上：库里没有第二份扁平数组
Run = text | ref | link | asset 判别键 t 开放扩展 text { t, v, marks? } 格式是 run 的属性，不是另一个实体 ref { id, t, to?, flavor?: '#', flavor '#' ＝ 行内 # 露面（指向标签类或实例） label?, marks? } label 只是插入时的快照，显示名一律现算 link { id, t, v, url, marks? } 外链：v 是显示文本，不产生块间边 asset { id, t, asset, label?, w?, h? } asset ＝ 内容 hash（字节住资产库）；永不带 marks label/w/h 是快照与布局提示，不是真相 ── 资产是独立对象（不是第二个内容实体，也不是 run 的载荷） ── AssetMeta = { hash, mime, size, w?, h?, createdAt } bytes 只在资产库记录里 AssetView = { state: 'ready' | 'missing' | 'unavailable', mime?, url?, w?, h? } state 是**现算**的：missing ＝ 库里没有这份 hash unavailable ＝ 资产库本身打不开（两种建议不同） AssetStorePort = { put(blob) · get(hash) · stat(hash) · keys() } v1 ＝ IndexedDB 内容寻址（qua.assets）；将来按库根换文件夹适配器 ── 实例（obj）不新增类型：props._tags 非空的块就是一条记录 ── 记录 = Block { props: { _tags: [标签 id] } } 值住它自己的 props（同一个属性袋）；正文里那枚 #名 只是一次提及，不写 _tags 目标身份由 RefView.kind 现算：tag / obj / page（不落盘） RefView = { label, state: 'resolved' | 'dangling', kind?: 'tag' | 'obj' | 'page' } Anno = { id, range: {start,end}, quote?, version? } ── 两套坐标：所有 start/end/off 都要先问自己用的是哪套 ── plain 文本字符数 ＋ 每个原子算 1 格（与 DOM 同系） 选区 / 光标 / IME / run 切片 / anno.range 用它 projection plainText 里的位置：原子贡献 0 格 引文快照用它（quote.exact 必须是投影的子串） 换算走 projectOff / projectRange，别手算
原子是不可分节点（ref/link/asset）：位置由邻居携带，删它一定是显式动作—— 不需要「原子在字符串里占一格」的占位符，也不需要偏移映射。格式随 run 走， 打字继承邻位格式是序列的自然结果。区间（annos）按需物化，只在被引用时存在。
三、写路径：一次用户动作 ＝ 一笔事务 ＝ 一批 opTx 是唯一的模型写入口；失败整批回滚，没有「半批」
① 入口
键位 / 菜单 / 斜杠
bindings.ts 一张表供五处共用；when.ts 求值上下文键
② 声明
命令（{{COMMANDS}} 条）
纯语义：capability / undoable，没有 key、没有 context
③ 实现
handler ＋ App 门面
命令不知道 UI 长什么样；最终落到内存文档
④ 事务
KbClient.tx
patch / insert / move / remove / restore / setProp / setAnnos
⑤ 产出
Op[] ＋ Change[]
Op 给存储，Change 只做失效通知（不带 payload）
⑥ 落盘
StoragePort.commit
单写者串行队列；localStorage 只出现在一个适配器里（arch [20]）
Op — 持久化事件（6 类）
{ e: 'block', id, op: 'upsert', value: { content?, parent?, index?, props? }, at } { e: 'block', id, op: 'delete', at } 只落操作根一条，子树不可见是继承来的 { e: 'prop', block, name, op, value?, pos?, at } { e: 'alias', block, name, op, pos?, at } { e: 'list', block, list, op, at } { e: 'anno', block, id, op: 'set' | 'delete', value?, at } 只在真被引用时出现
结构用 parent ＋ index 表达，不另造 insert 事件——「它现在在哪」只有一种说法。格式与原子的一次改动就是一条 upsert{content}：内容整组替换，不是逐段记差。实例字段写入＝一条 prop.set／prop.delete，没有「实例」专用 op。
落盘：两种宿主，三条不可逆契约
qua.db（Electron）
每个库一份 SQLite（主进程单写者，WAL）。当前是 临时形状：workspace(id=1, json, saved_at) ＋ settings ＋ meta ＋ op_log（只建表、不接写入）。schema 版本＝PRAGMA user_version（唯一判据）
qua.workspace（web）
整库（块森林；行内内容与区间都在块上），套一层信封 { backend, envelope, data }。浏览器没有用户可选目录的同等语义 ⇒ 单窗口单库
qua.device
设备态：主题 / 槽宽 / 钉住清单（不进 KB）
qua.assets
资产库：Electron 走每库 assets/<hash前2>/<hash> ＋ .json 侧车（字节是真相、侧车可重建）；web 仍走 IndexedDB hash → { mime, size, w?, h?, createdAt, bytes }。内容寻址 ⇒ 同字节只存一份
两个存储之间**没有跨库事务**：写图片的顺序固定为 字节先落 → 引用后落（put 成功才写 run）。崩在中间只留孤儿字节（无害）； 反过来会留下一枚指向空字节的 run。v1 无 GC，删 run 不回收字节。
开发阶段不做旧数据迁移：WORKSPACE_VERSION + 1 ＝ 旧库显式作废重 seed。 接库之后库内换形状走 user_version ＋ 只加不删迁移 ＋ 迁移前快照（实测：版本号随事务原子回滚）。 换键／换库名 ＝ 用户数据静默消失，所以它们被逐字钉死在门禁里。
四、读路径：一个门面，不给「遍历全库」的入口方法只按 id 取或按子树取
结构读
get(id) · children(id)
roots() · parentOf(id) · pathOf(id)
阶段 1 实现可以整库缓存，但调用方写不出「遍历全库」——否则懒加载那天要改遍每个调用方。
语义读
resolveAlias(name) · allPaths()
pages() · tags() · trash()
fieldsOf · tagsOf · journalDay
页／标签／回收站都是派生：没有第二存放处，每次从森林现算。fieldsOf(记录 id) 同时供属性区与行内实例字段卡，值只写记录块。
查询与反向
query(spec) · backlinksOf(id)
backrefBlocksOf(id) · annotationsOf
QuerySpec ＝ where（ref / tag / text / todo / prop / all / any / not）＋ sort ＋ limit。
五、「一切皆块」落在哪：身份是派生的，位置只是默认落点不再造 Page / Tag / Journal 实体
页
带 page 露面的块；页名＝主别名，正文是描述
日记
有 _date 的块；日期是只读投影，不进正文，全局一天一个
标签
带 tag 露面的块；归属在 props._tags，只有块级一处入口写它，渲染成行右端标签槽 .blk-tags 里的 chip（不占正文）。正文里敲的 #名 是提及（ref run），不写归属
实例（obj）
不是新类型：props._tags 非空的块就是那个标签的一条记录（归属即实例，不看身份与正文）。行内 #名 的 ref run 指向它，但那只是提及；值住它自己的 props（同一个属性袋），字段来自标签声明；⌥ 字段卡与属性区共用同一行渲染器，值只写记录块
属性
键＝定义块的 id ⇒ 改显示名不动任何值，两个插件撞名也不冲突
类型
唯一「值必须来自封闭注册表」的字段；声明（纯数据）与绑定（渲染器）分家
视图
对真实树的一次渲染；视图状态（滚动/折叠/宽度）外挂，不入 KB
侧栏
一个槽，里面是一列块；堆叠归槽，tab 归块
落点
页（新建 / @ 建页）与身份（tag / schema / journal）创建时物化在森林顶层；记录 / 笔记落当天。标记为页 原地；提取为页 才把块连子树搬到顶层，并在原位置留一枚引用。用户世界仍没有「根」：无根视图、无「提取为无名根」
三条不变量
A
位置＝默认落点，不是不变量：身份块创建时物化在顶层，此后移动/加露面不再强制移出——被卷进所附内容的删除由软删兜底。
B
正文语义：身份块的正文是名字或投影，内容写路径一律不许改它（一个 canWriteText 判据喂给所有写路径）。
C
存在：软删除 ＋ 同地址复活——删了能回来、类不分裂；恢复是摘标记回原位。
B、C 在 core/ 里维护，只查被操作的那一块自己，不扫子树——代价放到低频入口，让高频出口零判断。
qua · 一切皆块 · 块的身份与内容槽：id / content / children / created / modified / props 结构取自代码类型与架构断言；数字由 render 脚本现读
