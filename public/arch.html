二、数据结构：一片森林，行内内容是块上的一串 run落盘形状见 src/core/storage/shape.ts · 类型见 src/core/runs.ts
Block { id: string 32-hex UUIDv7 content: Run[] 行内内容＝run 序列；空块＝[] children: Block[] 子树；整库是一片森林，没有「页实体」 created: number 出生时刻（墙钟毫秒）。必填：不可能缺席，所以不是属性槽 modified: number 最后一次改动（只在编辑边界更新，并进内容那条 upsert） annos?: Anno[] 可引用区间：只在被引用时才存在（不写空数组） props?: { 属性袋：键＝定义块的 id，不是名字 _type? 封闭注册表：core/outline · core/divider · core/collection-widget · core/view-embed _icon? lucide:<name> 或字面文本 _date? 有它 ⇒ 日记块（只读、全局一天一个） _aliases? 地址：0..N，首个是主名，全局唯一 _lists? 露面：page / tag，可兼位、可空 _display? 这一行显示别名还是正文 _tags? 分类归属：存标签块的 id（有序） _belongsTo? 归属（filed-under）：子块 → 上级，任何块都能配、可多父 _deletedAt? 有它 ⇒ 这块被软删了（子树不可见是继承来的） _kind? 有它 ⇒ 属性定义块（种类是它自己的数据） _query? 有它 ⇒ 查询块（值＝where 条件）；结果按表面实例冻结，不在这里 _mounts? 块底那几栏：local（自己带 spec/views）/ linked（只有指针） _views? 命名视图（列/序/分组…）：这一块怎么看，换设备要一致 _activeView? 当前激活的视图 id；缺席＝这一份源的默认看法 _embed? 露面：{ block, view } 指针。看法住在源块的命名视图上 _items? 集合组件的引用列表：块 id[]（有序引用，不是 children —— 零级联） _fieldDefs? · _choiceScope? · _ownProps? · _uiPosition? [定义块 id]: unknown 用户/插件定义的字段值 } } Doc = { roots: Block[], folded?: Record<id, true> } 折叠态在 Doc 上，不在块上 Workspace = { version: {{WORKSPACE_VERSION}}, blocks: Block[], activeId: string, savedAt: number } 行内内容与区间都住在块上：库里没有第二份扁平数组
Run = text | ref | link | asset 判别键 t 开放扩展 text { t, v, marks? } 格式是 run 的属性，不是另一个实体 ref { id, t, to?, flavor?: '#', flavor '#' ＝ 行内 # 露面（指向标签类或实例） label?, anchor?, marks? } 显示名＝现算 ＋ anchor 覆盖（用户写的这一处）；label 只在 dangling 且无 anchor 时兜底 link { id, t, v, url, marks? } 外链：v 是显示文本，不产生块间边 asset { id, t, asset, label?, w?, h? } asset ＝ 内容 hash（字节住资产库）；永不带 marks label/w/h 是快照与布局提示，不是真相 ── 资产是独立对象（不是第二个内容实体，也不是 run 的载荷） ── AssetMeta = { hash, mime, size, w?, h?, createdAt } bytes 只在资产库记录里 AssetView = { state: 'ready' | 'missing' | 'unavailable', mime?, url?, w?, h? } state 是现算的：missing ＝ 库里没有这份 hash unavailable ＝ 资产库本身打不开（两种建议不同） AssetStorePort = { put(blob) · index() · urlOf(hash) · onAddressChange(fn) } 端口给地址不给字节：桌面版＝ qua-asset://<hash>（常量） 浏览器＝实现内部自己建/回收 Blob URL，调用方零生命周期 ── 实例（obj）不新增类型：props._tags 非空的块就是一条记录 ── 记录 = Block { props: { _tags: [标签 id] } } 值住它自己的 props（同一个属性袋）；正文里那枚 #名 只是一次提及，不写 _tags 目标身份由 RefView.kind 现算：tag / obj / page（不落盘） RefView = { label, state: 'resolved' | 'dangling', kind?: 'tag' | 'obj' | 'page' } Anno = { id, range: {start,end}, quote?, version? } ── 两套坐标：所有 start/end/off 都要先问自己用的是哪套 ── plain 文本字符数 ＋ 每个原子算 1 格（与 DOM 同系） 选区 / 光标 / IME / run 切片 / anno.range 用它 projection plainText 里的位置：原子贡献 0 格 引文快照用它（quote.exact 必须是投影的子串） 换算走 projectOff / projectRange，别手算
原子是不可分节点（ref/link/asset）：位置由邻居携带，删它一定是显式动作—— 不需要「原子在字符串里占一格」的占位符，也不需要偏移映射。格式随 run 走， 打字继承邻位格式是序列的自然结果。区间（annos）按需物化，只在被引用时存在。

Op — 持久化事件（3 类，一格一个地址）
{ e: 'block', id, op: 'upsert', value: { content?, created?, modified?, parent?, prev? }, at } 新块的 genesis 一次说全：位置＋出生＋时刻＋正文 { e: 'block', id, op: 'exist', state: 'present' | 'deleted' | 'purged', at } { e: 'prop', block, name, op: 'set' | 'delete', value?, at } 含 _aliases／_lists／_tags 整袋值 { e: 'anno', block, id, op: 'set' | 'delete', value?, at } 只在真被引用时出现
结构用 parent ＋ prev（前兄弟 id）表达，不另造 insert 事件——「它现在在哪」只有一种说法。不用整数下标：下标只对「那一刻的兄弟列表」有意义，同一个下标在短列表上会静默落到别处，而 op 是不可逆历史。格式与原子的一次改动就是一条 upsert{content}：内容整组替换，不是逐段记差。存在是一个格、三个值：软删是可恢复的 deleted，撤销一次插入是终态 purged——曾经它们共用一个 delete，于是撤销后重开，块会从回收站冒出来。一格只有一个地址：地址与露面走 prop 的整袋值，不另立 alias／list 两种「按项增量」——同一个格两条账会让重放顺序决定结果、幂等性也破。只有「绝对的、按格寻址的 set」才能满足应用两次等于一次，而那是撤销与同步的共同前提。
落盘：两种宿主，三条不可逆契约
qua.db（Electron）
每个库一份 SQLite（主进程单写者，WAL）。块是自己的行：Block（正文 run 序列／annos／时刻／落库编码的 parent＋left／软删）＋ BlockProperty（一格一行，有序列表拆行＋pos）＋ BlockAlias（地址，主键是名字）＋ BlockList（露面）＋ meta／settings／op_log（变更流，与内容行同一个事务追加；整份替换＝新 genesis：清旧日志、序号归零，再把这一批 op 写进去）。schema 版本＝PRAGMA user_version（唯一判据，当前 {{DB_SCHEMA_VERSION}}）
编码在哪
「一个块长成哪几行」只有一份定义（storage/db-rows.ts）；主进程只做通用 SQL（表名/列名白名单，不认识块）。一次编辑只写动过的那几块 ⇒ 写成本不随库体量增长
qua.workspace（web）
整库（块森林；行内内容与区间都在块上），套一层信封 { backend, envelope, data }。浏览器没有用户可选目录的同等语义 ⇒ 单窗口单库
qua.device
设备态：主题 / 槽宽 / 左右槽的卡片清单 / 钉住清单（不进 KB）
assets/（Electron）
资产库：一图一行一文件 —— 元信息在 qua.db 的 assets 表（hash / mime / size / w / h / added_at），字节在 assets/<hash前2>/<hash>.<ext>，没有侧车；渲染层拿到的是地址 qua-asset://<hash>（壳的协议处理器直出文件），没有对象 URL 生命周期。web 仍走 IndexedDB hash → { mime, size, w?, h?, createdAt, bytes }。内容寻址 ⇒ 同字节只存一份；后缀只写不读（类型只从行里来）
两个存储之间没有跨库事务：写图片的顺序固定为 字节先落 → 引用后落（put 成功才写 run）。崩在中间只留孤儿字节（无害）； 反过来会留下一枚指向空字节的 run。v1 无 GC，删 run 不回收字节。
开发阶段不做旧数据迁移：WORKSPACE_VERSION + 1 ＝ 旧库显式作废重 seed。 接库之后库内换形状走 user_version ＋ 只加不删迁移 ＋ 迁移前快照（实测：版本号随事务原子回滚）。 换键／换库名 ＝ 用户数据静默消失，所以它们被逐字钉死在门禁里。
两个纯函数：变化代数的全部撤销 / 导出 / 导入 / 同步收端 / 崩溃恢复 / 块历史，全是它们的组合
diff(a, b) → Op[] 把「a 变成 b」表达成格写入 applyOps(forest, ops, 目标) 原地写格，对象身份不变
四条性质（每条都能单独证伪）：① applyOps(a, diff(a,b)) 与 b 逐字节相等；② diff(x,x) == []；③ 发射序＝目标森林先序（父 op 先于子 op）；④ 同一次 diff 跑两次字节相同（at 从目标森林派生，不取墙钟）。
撤销
applyOps(s, diff(s, 快照)) —— 与一次普通编辑同一条路，不再「清四表 + 整库重写」
索引
唯一的宣布者是事务出口 store.apply(ops)：按 op 增量修补，不整库作废；订阅者只被通知一次
回滚
事务失败走回滚日志（O(动过的块)），不是整库快照。它不是逆 op：生命周期＝一个调用，不落盘、不进历史
为什么 applyOps 必须原地写格：索引存的是块的活引用。若替换块对象（CoW／JSON.parse），索引会静默失效——它手里那批对象当场过期，而没有任何一层会报错。 ⇒ 这也是「撤销不再需要 forestReplaced 旗标」的原因：旗标存在的唯一理由是旧机制的实现细节。

五、查询模型：条件是内容，结果是一次求值的投影src/core/query.ts（条件与求值）· query-view.ts（冻结）· query-draft.ts（表单草稿）
QuerySpec 存进 props._query 的唯一形状
QuerySpec { where: QueryNode 条件树；canonical JSON 才落盘（键序固定） scope?: 'subtree' | 'all' 从哪个容器往下找；缺省 subtree sort?: SortKey[] 成员顺序（取哪些），在 limit 之前生效 limit?: number 排序之后截断；缺省不限 } ── 七个原子 ＋ 三种组合（每个原子都必须在 canonicalSpec 里有一支） ── { ref: 块 id } 反链的最小形态：只认 id，不认 label { tag: 标签 id } 按归属边（_tags）判；名字解析不到＝空集 { text: 串 } 正文投影包含；未链接提及走这里，不算反链 { todo: 三态 } todo / done / none（有槽未填 ≠ 不是任务） { prop: { id, 算子 } } 通用路径：键是定义块 id，改显示名不动语义 { journal: 'YYYY-MM-DD' } 那一天的块下面（范围条件） { role: 'journal' } 是日记块本身（成员条件） { all } / { any } / { not } 可嵌套；能组合表达的，不另造专用键
三种东西别混：条件（入 KB、进撤销）／结果集（一次求值，冻结在表面实例）／内容（永远按 block id 现读）。 专用键每多一个，canonicalSpec 就多一处会漏的分支，而漏掉的表现是「条件看着没变、结果对不上」。 role 与 journal 的分工写死：范围条件把日记块当容器（钻进那天下面），成员条件把它当结果（天自己入选）。
九个算子 PropOp —— 一条属性条件只带一个算子
值比较
eqneqcontains gtgteltlte
槽存在
exists
空/非空

值比较：有这一槽才比，没有就是不匹配。neq 同一条口径——否则它会变成「绝大多数块」。 gt／lt 只在同一量纲上比；比不了返回空 ⇒ 不匹配（按字符串比会让 true > 5 成立）。
empty 与 exists 必须分开：「未填的任务」是有槽、值为空，「不是任务」是没有这一槽；合成一个算子就再也问不出前者。 九个算子必须逐支进 canonicalSpec，漏一支＝条件静默丢失。
构建器 条件行 ⇄ JSON，同一份数据
DraftRow { kind: todo|tag|text|prop, field?, op?, value? } QueryDraft { mode: all|any, rows[], scope, limit?, sort?, verbatim? }
specOfDraft(draftOfSpec(s)) 与 canonicalSpec(s) 逐字节相等（有单测）；两边各写一份转换，就一定会在某个算子上分叉。 拆不成行的嵌套（not 里套 any）整块走 JSON，不拆——拆了再拼回来就不是它自己。一次「应用」＝一笔事务＝一轮撤销；JSON 解析失败保留原文，绝不静默清空。

selfId 只负责解析 $self，不再顺带排除——「想解析它、又不得不把它从结果里去掉」是把两件事塞进同一个字段的后果。 挂载宿主与查询块自己一律不进结果：那是位置的性质，不是条件的性质。相对条件解析出空值 ⇒ 永不命中，不退回全库。
FrozenResult = { specKey: string canonicalSpec(_query) 的 JSON contextKey: string selfId / scopeId / excludeIds 的稳定串 hits: QueryHit[] }
谁持有
ViewHost（center）、每个 mount tab、EmbedBody、dock 卡——每个表面实例一份
何时重算
首次显示；specKey 变（条件被编辑/撤销）；contextKey 变（换宿主/表面）；用户点刷新
不落盘
只在内存：刷新不写块、不改 modified、不进撤销。_queryResult 已删且不得复活
stale
外部改动命中当前 hits ⇒ 只点亮提示，不改列表；刷新才移除（移除条数给 toast）
代价
同一条件在两个表面各有一份快照：一个刷新，另一个仍是旧的——这是表面状态，不是内容版本
为什么结果不入库：条件相同、数据相同 ⇒ 结果相同。结果不是用户写下的东西，是数据的一个投影；投影存进内容层，就必然说谎——撤销会撤掉「上一次刷新」、跨端结果不同、外部改了数据而界面看不出它在说谎。 「编辑时行不跳」由实例冻结满足，不需要把它存成内容。

三个状态轴正交 不要互相推导
轴存哪判据与边界
位置cards 顺序拖拽改序、跨槽搬；数组位只表示顺序，条目有稳定 id
收起collapsedCards[id]只隐藏 body，不销毁编辑器；按卡片实例 id，跨槽移动后状态跟着卡走
单卡solo[side]只看这一张，由槽层用 data-solo 过滤其它卡；目标不可见时不生效（状态保留，回来再生效）
三个轴各存各的：「收起」与「单卡」合成一个值，就会出现「收起了却还占着单卡位」。 重画槽时卡片是 entry，按顺序原地不动——搬一个正在编辑的 contenteditable 会丢焦点与光标（每敲一个字跳一次）。
四条纪律 踩过的坑，别推翻
1
卡壳只有一个产地（ui/dock.ts）：头／收起／单卡／关闭／拖拽。窗口、组件、派生共用一套，否则「所有卡片都支持 X」一定会漏掉某一张（真踩过：手写的头没有折叠按钮）。
2
卡头只有三颗控件，每张卡同构。作用于内容的动作（回到本月、清空回收站）长在 body 里、贴着它作用的东西——卡头是跨卡扫视的一列，多一颗按钮整列图标就错开。
3
hidden（没有内容）≠ data-collapsed（用户收起）：前者是可用性，归卡片内容的主人；后者是布局。同一个值表达两件事，就再也分不开「没有主体」和「收起了」。
4
槽内只许纵向。卡片与卡片之间没有横向排列入口；小卡是 44px 的格子，单独一格一组，不参与卡片的折叠/单卡。

八、「一切皆块」落在哪：身份是派生的，位置只是默认落点不再造 Page / Tag / Journal / View 实体
页
带 page 露面的块；页名＝主别名，正文是描述
日记
有 _date 的块；日期是只读投影，不进正文，全局一天一个
标签
带 tag 露面的块；归属在 props._tags，只有块级一处入口写它，渲染成行右端标签槽 .blk-tags 里的 chip（不占正文）。正文里敲的 #名 是提及（ref run），不写归属
实例（obj）
不是新类型：props._tags 非空的块就是那个标签的一条记录（归属即实例，不看身份与正文）。行内 #名 的 ref run 指向它，但那只是提及；值住它自己的 props（同一个属性袋），字段来自标签声明；⌥ 字段卡与属性区共用同一行渲染器，值只写记录块
属性
键＝定义块的 id ⇒ 改显示名不动任何值，两个插件撞名也不冲突
类型
唯一「值必须来自封闭注册表」的字段；声明（纯数据）与绑定（渲染器）分家
查询
有 _query 的块：条件是内容（入 KB、可引用、进回收站），结果只是表面实例的冻结快照（第五节）
视图
对一份源的记录怎么排、怎么画；配置住拥有者（_views／_activeView），滚动/选中/冻结结果外挂、不入 KB
侧栏
一个槽，里面是一列条目：窗口卡／组件卡／派生卡／小卡。堆叠归槽、卡片归块；清单是设备状态（第七节）
落点
页（新建 / @ 建页）与身份（tag / schema / journal）创建时物化在森林顶层；记录 / 笔记落当天。标记为页 原地；提取为页 才把块连子树搬到顶层，并在原位置留一枚引用。用户世界仍没有「根」：无根视图、无「提取为无名根」
三条不变量
A
位置＝默认落点，不是不变量：身份块创建时物化在顶层，此后移动/加露面不再强制移出——被卷进所附内容的删除由软删兜底。
B
正文语义：身份块的正文是名字或投影，内容写路径一律不许改它（一个 canWriteText 判据喂给所有写路径）。
C
存在：软删除 ＋ 同地址复活——删了能回来、类不分裂；恢复是摘标记回原位。
B、C 在 core/ 里维护，只查被操作的那一块自己，不扫子树——代价放到低频入口，让高频出口零判断。
同一条判据贯穿后三节：数据只回答「是什么」（_query／_items／_embed 决定源）， 配置只回答「怎么看」（拥有者的 _views），表面只回答「在哪看」（center／mount／embed／dock）。 各自只有一份真相，所以「改一处」不会悄悄改掉另一处。
