# Widget：槽里的露面

> 这份只回答一件事：**侧槽里的一个格子是什么、它从哪来、能长成什么样。**
> 它不替代 `模型-一切皆块.md`；相反，它把「槽」这一层接到那套模型上。

---

## 0 一句话

> **Widget 是「槽里的一次露面」，不是一种新的实体。**
> 一块数据仍然住在块里；一条动作仍然是一条命令；槽只负责「把谁放在哪」。

把三根轴分开，后面的决定就都顺了：

| 轴 | 回答什么 | 例子 |
|---|---|---|
| **Source（真相）** | 数据是什么 | 一棵块树、一个查询、一组块 id |
| **View（渲染）** | 怎么画 | 大纲、表格、看板、日历 |
| **Surface（露面）** | 出现在哪 | 正文一行、中心全屏、槽里大卡、小卡 |

- **Widget 是 Surface 轴**：槽里的一个露面，`small` 或 `large`。
- **一源多视是 Source × View 轴**：同一份真相，可以有多个渲染。
- **View Block 是两条轴的接点**：一个块，带 source ＋ view type ＋ config；它自己又可以出现在多个 Surface。

---

## 1 一条列表，三种条目

槽的设备状态仍然只有一条有序列表：

```ts
interface DockSlotPrefs {
  open: boolean
  width: number | null
  cards: string[]   // 有序
}
```

`cards` 里的字符串分三种：

| 条目形状 | 解析成 | 尺寸 | 有没有块 |
|---|---|---|---|
| `cmd:<命令名>` | **小卡**：一个命令的快捷方式 | small | 没有 |
| 32 位块 id | 一个块的一次露面（窗口卡；以后也可以是组件块） | large | 有 |
| `belongs`／`journal`／`inspect`／`backrefs` | 宿主现算的派生卡 | large | 没有 |

`cmd:` 不是块，所以**同一个命令可以同时出现在左右两槽**；块 id 仍然全局最多一张窗口
（同一个块不会在两边各开一份）。

---

## 2 两种尺寸，一个流

- **small**：44×44 固定，图标（或自定义小视觉），点击＝命令。不随槽宽拉伸。
- **large**：占满整行，用现有卡壳（头／折叠／单卡／关闭／拖拽），body 由渲染器决定。

槽内容是一个 `flex-wrap` 流：小卡横排、自动换行；大卡占满一行。顺序仍是一条线
（DOM 顺序 = `cards` 顺序）；换行只是排版，不是第二层列表。

默认左槽：四个快捷（回到今日／新建页面／命令面板／前一天）＋ 归属树 ＋ Daily note；
右槽：检视卡 ＋ 反链。

---

## 3 组件块：块类型 ＋ 露面声明

有内容/配置的 Widget 是**视图块**；没有内容/配置的纯动作是 `cmd:`。判据只有一句：

> **这个 Widget 的配置/数据要不要跟着库走、要不要能出现在正文或被引用？**
> 要 → 块；不要 → 命令或宿主单例。

块类型声明里加两格露面：

```ts
interface TypeDecl {
  children: 'content' | 'none'
  text: 'editable' | 'readonly'
  widget?: {
    slot?: { size: 'small' | 'large'; height?: 'compact' | 'medium' | 'tall' }
    body?: 'row' | 'inline'   // 没有这一项 ＝ 只能出现在槽里
  }
}
```

- `slot`：槽里的卡/瓦片。
- `body`：正文里的露面。`row` 是只读摘要行（点击打开完整卡）；`inline` 是完整 UI 嵌入正文，
  后置，且必须有自己的非编辑宿主（不能和父编辑器共用一个 contenteditable）。
- 同一个块可以同时在正文是一行、在槽里是一张卡：这是**一源多视**，配置共享、undo 共享。

渲染绑定与块类型声明分开：

```ts
interface WidgetRenderer {
  render: (ctx: WidgetCtx) => HTMLElement   // 只画 body / 小卡内容
  update?: (el: HTMLElement, ctx: WidgetCtx) => void
  destroy?: (el: HTMLElement) => void
}
```

`WidgetCtx` 给只读数据、命令调用、导航、外挂视图状态与宿主原语；**不把整片森林交出去**。

## 4 集合卡：模型里的命名容器

「接受一组块 id，渲染一组块」是**集合卡**，不是设备状态清单：

```ts
_type: 'core/collection-widget'
_items: [blockId, blockId, ...]   // 有序引用，不是 children
```

- **不是 `children`**：否则会污染子树读路径（根、反链来源、折叠、复制）。
- **零级联**：删集合卡不删里面的块；删块不删引用，留悬空项（块恢复后自动回来）。
- 一个或多个都行：一个＝链接卡；多个＝收藏／阅读清单。
- 想要**可编辑**的单块，用窗口卡（内容块 id）；集合卡是引用列表。

---

## 5 脚本与插件

**脚本 ＝ 命令/插件，不是卡片里的一段内联 JS。**

- 卡片只存「调用哪条命令/哪个类型 ＋ 参数」；代码住在插件模块里。
- 脚本通过受管门面读 query/index、调命令、走事务写；不碰裸存储、Node 内建、密钥、单写通道旁路。
- 禁用插件 ⇒ 撤销注册；卡片降级成占位，位置不 reflow，数据保留。
- 想给卡片传参数，用脚本动作块（`command + args`），不要把 JSON 塞进 `cmd:` 字符串。

---

## 6 表格：View 类型，不是新的 Widget 种类

表格是**视图块**，不是 Widget 的新 kind：

```ts
_type: 'core/table-view'
_source: { kind: 'subtree', blockId } | { kind: 'query', spec } | { kind: 'collection', ids }
_columns: [{ propId, label, width, format, editable }]
_sort?: { propId, dir }
_depth?: number
```

- 行＝source 里的块；行身份是块 id；表格不拷贝行。
- 单元格编辑走宿主的字段编辑器/纯文本输入，提交走命令/事务，写回 source。
- 排序/筛选/分组/列宽/滚动/选中是视图状态，外挂、按露面实例键控，不进 KB。
- 它通过 `slot`/`body` 露面接进 Widget 系统；`cards` 只存它的块 id。

---

## 7 宿主与插件的分工

| 归宿主 | 归插件 |
|---|---|
| 槽的顺序、流式布局、拖拽、移除 | — |
| 大卡壳（头／折叠／单卡／关闭）；小卡 44px 格 | — |
| 数据读取（query／index）、事务订阅刷新 | 声明数据源、格式化 |
| 命令执行、权限、undo | 交互要调的命令 |
| 主题 token、UI 原语 | 用原语搭 body，不写裸色 |
| 生命周期、焦点、滚动 | renderer 的内部状态／定时器 |
| 配置入块 props、位置入 prefs、视图状态外挂 | 提供配置 schema／默认值 |

**插件不拥有卡壳、不拥有位置、不直接写 KB。** 这三条守住，插件画什么都拆不掉应用。

---

## 8 退化与生命周期

| 情况 | `cmd:` 小卡 | 组件块（自定义小卡／大卡） | 窗口卡 | 派生卡 |
|---|---|---|---|---|
| 命令／类型不可用 | 占位瓦片 | 占位卡／未知类型降级 | 块缺失不渲染 | 不渲染 |
| 插件卸载 | 占位 | 数据保留，重新启用恢复 | — | — |
| 从槽移除 | 移除字符串（无块） | 移出 `cards`，块留着 | 移出 `cards`，块不动 | 移出 `cards` |
| 再打开 | 画廊「动作」 | 画廊「已保存的组件」 | 搜索／Shift+点 | 画廊「系统」 |

`collapsedCards`／`solo` 只对 large 有意义；small 没有折叠／单卡，只有移除。
位置稳定优先于可用性过滤——不可用不要 reflow。

## 9 当前状态（诚实地分开）

**已落地：**

- `cards` 支持 `cmd:<命令名>`；同一个命令可同时出现在两槽。
- 命令声明加可选 `tile: { icon }`；只有带它的命令进「添加组件」画廊。
- 小卡 44×44、流式换行；可加、可移、同排拖序；命令不可用时保留占位。
- 默认左槽四个快捷；右槽不变。
- **组件块类型**：`TypeDecl.widget`（`slot` 槽里的卡／`body` 正文里的露面）；
  槽里按类型分派（组件块 → renderer，内容块 → 窗口编辑器）。
- **集合卡**：`core/collection-widget`，`_items` 有序引用（不是 children）；
  「添加组件 → 新建收藏」建块并开进槽；拖块进来＝加引用；「选择块」可加已有块；
  行首手柄可拖序；`×` 只摘引用不删块；悬空引用保留。
- **正文露面 `body: 'row'`**：声明了 `body` 的组件块在正文里是一行**只读摘要**
  （图标 ＋ 名字 ＋ 几条 ＋「打开」）；点它打开那张卡、Shift+点开右槽，中心不动。
  摘要与槽里那张卡**共享配置**（同一格 `_items`，一源多视）；悬空引用在摘要里明说
  「N 条（M 条已删）」，不替用户藏掉。插入走斜杠菜单「收藏」，与分割线同一个插入形状。
- 断言：`A18`（44px／顶对齐／大卡整行）、`T136`（小卡点击走命令面／加／移／拖序）、
  `T137`（新建收藏／拖入／× 只摘引用）、`T138`（选择块加两条／手柄拖序）、
  **`T139`（正文组件行：摘要不进正文／点开卡／Shift 开右槽／与槽共享配置）**、
  `collection` 单测（形状／去重／空集合／复制／拖序／**露面与摘要**）、
  `device` 单测（`cmd:` 跨槽、默认值、`pins` 并入）。

**还没做（按顺序）：**

1. `body: 'inline'`（完整 UI 嵌进正文，后置，且必须有自己的非编辑宿主）。
2. 脚本/插件门面：`registerWidget` 门面（底层仍是块类型/命令）。
3. 表格视图：`core/table-view`，source/columns/单元格编辑。

### 9.1 正文露面的两条契约（M4 落地时定下的）

正文里那一行**占了 `.tx` 的位置，却不是正文** —— 这是它唯一容易出错的地方，
所以三处必须一起对上（任何一处漏掉都是「看起来对、偶尔差一格」）：

| 处 | 契约 | 漏了会怎样 |
|---|---|---|
| 读数（`view/dom-text.ts`） | `isWidgetRow` ⇒ 长度 0、`readRuns` 跳过 | 一次 `readRuns` 就把「收藏 3 条 打开」写成真正文，组件行从此消失 |
| 落点（`textEndOff`） | 光标落在组件行**之前**，不是之后 | 打字排到摘要后面，模型里仍是正文末尾 |
| 清理（`ALLOWED_ROW_CHILDREN`） | 登记 `widget-row` | 第一次收光标把整个组件行当游离节点删掉 |

**为什么「打字再看 content」测不出第一条**：组件行的 `.tx` 是 `data-readonly`，
`syncFromDom` 那条路根本走不到它身上 —— 那样写出来的断言是**恒绿**的
（删掉 `isWidgetRow` 的读数分支它照样过，实测过）。要验就**直接调读数层**
（冒烟经诊断面的 `readRuns` 打在 `.tx` 上，结果必须是空）。

**一源多视的判据**：摘要与卡读的是**同一格 `_items`**，不是「卡有一份、行有一份」。
所以加一条引用，两处同时变；撤销也是同一笔。

---

## 10 三条不变量

1. **槽只存位置**：`cards` 是 id 列表，不是数据副本。
2. **块是真相**：同一块在正文/槽/查询里编辑，共享 store 与 undo；视图状态外挂。
3. **插件不拥有 chrome**：卡壳、位置、写通道归宿主；插件只画 body、只调命令。
