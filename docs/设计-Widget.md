# Widget：槽里的卡

> 这份只回答一件事：**侧槽里的一个格子是什么、它从哪来、能长成什么样。**
> 它不替代 `模型-一切皆块.md`；相反，它把「槽」这一层接到那套模型上。

---

## 0 一句话

> **槽里的卡只有两种：窗口（渲染某个块）与家具（宿主现算）。Widget 指后者。**
> 一块数据仍然住在块里；一条动作仍然是一条命令；槽只负责「把谁放在哪」。

历史上 widget 曾是「一种块类型在槽里的露面」（块类型声明里有一格 `widget`）。
那条路随「收藏」的退场一起拆掉了：它唯一的意义是为一张卡在库里造一个块，
而「块与 widget 解耦」之后，**widget 从此是宿主侧的东西**——像派生卡那样住在装配层，
不经过块模型。块类型声明回答的只有「这一行的骨架是什么」。

| 轴 | 回答什么 | 例子 |
|---|---|---|
| **Source（真相）** | 数据是什么 | 一棵块树、一个查询 |
| **View（渲染）** | 怎么画 | 大纲、表格、看板、日历 |
| **Surface（露面）** | 出现在哪 | 正文一行、中心全屏、槽里大卡、小卡 |

## 1 一条列表，几种条目

槽的设备状态只有一条有序列表：

```ts
type DockEntry =
  | { kind: 'block'; block: string }          // 一个块的窗口（拖进来或打开）
  | { kind: 'shortcut'; block: string }       // 指向一个块的快捷小卡（常驻入口）
  | { kind: 'derived'; card: DerivedCardId }  // 宿主现算的派生卡
  | { kind: 'cmd'; command: string }          // 一个命令的小卡
  | { kind: 'utility'; face: UtilityFaceId }  // 工具面卡
  | { kind: 'tray'; id: string; title?: string; cards: DockEntry[] }  // 小卡的容器（§3）

interface DockSlotPrefs {
  open: boolean
  width: number | null
  cards: DockEntry[]   // 有序
}
```

**种类由 `kind` 说，不由字符串形状猜**：写入口按 `kind` 构造、渲染按 `kind` 穷举。
加一种来源＝编译期错误，而不是「那种卡不出现」。

| 条目 | 尺寸 | 有没有块 | 身份（`dockKey`） |
|---|---|---|---|
| `block`（窗口卡） | large | 有 | 块 id |
| `shortcut`（快捷卡） | small | 有（只是指针） | `shortcut:<块 id>` |
| `derived`（`inspect`／`belongs`／`backrefs`／`trash`／`calendar`） | large | 没有 | 派生卡 id |
| `cmd` | small | 没有 | `cmd:<命令名>` |
| `utility` | large | 没有 | `utility:<面 id>` |
| `tray`（收纳盘） | large | 没有（装的是小卡） | `tray:<id>` |

**盘是这条列表里的又一种条目**，不是第二层列表：它自己站一个位置、有自己的卡头，
里面的小卡仍是「身份 ＋ 顺序」两件事（§3）。

`cmd` 不是块，所以**同一个命令可以同时出现在左右两槽**；块仍然全局最多一张窗口
（同一个块不会在两边各开一份）。DOM 的 `data-card-id`、收起／单卡表、拖拽载荷
仍用扁平 key——换一串会让用户已折叠／已单卡的卡静默复位。

**快捷卡是家具，不是窗口的另一种状态**：它和窗口卡是 `cards` 里两条独立条目、
两个不同的 key，所以同一个块可以同时有窗口与快捷。窗口卡的 key 保持块 id 不变
（老设备状态里的 pin／收起／单卡都按它存），只有快捷卡带前缀。点击走打开块的
同一条路由：普通点＝中心，Shift＝侧槽加开窗口，⌘＝新页签，⌥＝属性面。
窗口卡卡头有「收成快捷」（关窗口、留一颗）；**没有**反向的「小卡转大卡」——
小卡只占 44px，删掉它是净亏，想摊开看直接 Shift+点加一张窗口即可。

**窗口卡不挑块**：槽是视口，不是类型的分派器。拖任意块进槽＝一张钉住的窗口卡，
Shift+点＝临时打开（重启即清，除非 pin）。

## 2 两种尺寸，一个流

- **small**：高度固定 44，宽度由这一行的列均分（列数 ＝ min(放得下几列, 实际几张)）；点击＝命令。
- **large**：占满整行，用现有卡壳（头／折叠／单卡／关闭／拖拽），body 由渲染器决定。

槽内容是一个网格流：小卡按列均分、自动换行；大卡占满一行。顺序仍是一条线
（DOM 顺序 = `cards` 顺序）；换行只是排版，不是第二层列表。
盘的 body 也是这个流（§3）——它不新增第二种排版。

默认左槽：四个快捷（回到今日／新建页面／命令面板／前一天）＋ 日历 ＋ 归属树；
右槽：检视卡 ＋ 反链。

## 3 收纳盘：只收叶子的小卡容器

> **一句话**：小卡攒多了要能收起来，而槽里唯一「自带把手、能开合」的东西就是卡——
> 所以收纳盘 ＝ **一张卡，卡头是把手，body 是小卡排**。没有第二种形状。

### 3.1 为什么是卡

1. 槽只有一条轴（顺序）和一个预算（竖向空间）。小卡是**叶子**：没有卡头、没有正文、
   没有收起／单卡／常驻，只有顺序 —— 所以它的占位随张数线性增长。
2. 收纳要的是「把 n 份占位压成 1 份，并且那一份**自带把手**」（能开合、能命名、能被拖走、能关掉）。
   只压不给把手，那是隐藏，不是收纳。
3. 槽里已经有的、自带把手的 O(1) 就是卡：卡头 ＋ 收起 ＋ 单卡 ＋ 关闭 ＋ 拖拽 ＋ 右键菜单。
   ⇒ 盘**不新增任何视觉词汇**：收起态与一张普通卡头同构。
4. **容器只收叶子**。窗口卡与派生卡自己就有容器语义（头／body／收起），收进盘等于第二个槽
   （第二套顺序、折叠、拖拽）。盘只收小卡 ⇒ 「关闭其它窗口」「置顶」「启动清理」这些
   扫 `cards` 的路径天然正确，一行都不用递归。

### 3.2 形状

```ts
| { kind: 'tray'; id: string; title?: string; cards: DockEntry[] }
//   id    ：设备状态里的稳定身份（改名、换槽都不变）；`dockKey` = `tray:<id>`
//   title ：可空。空 = 未命名，卡头显示「n 张小卡」
//   cards ：**只许** cmd / shortcut；深度恒为 1
```

- 「只许叶子」不是类型能表达的：判据落在**写入口**（只有这两个 kind 能被放进去）与
  **读入口**（见面下一条）。`cards` 的类型仍是 `DockEntry[]`，纵深靠判据守。
- 收起状态**复用 `collapsedCards`**（键就是 `tray:<id>`），不新增表、不新增判据：
  `isCardCollapsed` 仍是唯一入口 ⇒「收起全部」「单卡目标此刻展开」「收起时退出单卡」自动成立。
- 渲染：盘的 body 用**同一条**列规则（列数 ＝ min(这一行放得下几列, 实际几张)），
  只是换成盘的内容盒来算；槽与盘共用一份 band 渲染与一份列数函数。
- 卡头：`[grip] [chevron] 名字 ［n］ [单卡] [✕]`，按钮与普通卡同列（A24 继续成立）；
  静置只剩上下文（窗口路径／盘计数）或把手标，名字与按钮悬停进场（§7）——收起的盘头全键常驻。

### 3.3 操作

| 动作 | 手势 | 规则 |
|---|---|---|
| 建盘 | 小卡右键 →「收进新收纳盘」 | 容器**从内容里长出来**：盘插在那张小卡原来的位置，顺序感不变；不存在空盘 |
| 一次收完 | 盘头右键 →「把其余小卡收进来」 | 「这一排太碍事」是主路径，不是补充 |
| 收进去 | 小卡拖到**盘头** | 追加到盘末。收起／展开两态都成立（body 收起时，落点自然只剩盘头） |
| 移出来 | 小卡拖到槽里两张卡之间 | **落点决定容器**，没有「进入盘模式」这种状态 |
| 盘内排序 | 拖到某一格前后 | 与裸排同一条规则、同一份代码 |
| 收起／展开 | 点盘头（或槽头的收起全部） | 只藏 body，别的都不变 |
| 重命名 | 盘头右键 → 重命名（行内输入） | 单一入口；点盘头仍然是开合 |
| ✕ | **解散**：只摘把手，小卡留在原位 | 关容器不许带走成员 |
| 连同小卡移出 | 盘头菜单（唯一后果性动作） | ✕ 不该是破坏性按钮 |
| 空盘 | 自动解散 | **容器是内容的推论**：0 件就没有容器 |
| 单卡／拖盘 | 现有规则 | 盘是一个条目，这两件白拿 |

### 3.4 六条不变量

1. **只收叶子、不嵌套**：读到嵌套盘 ⇒ 成员摊平到原位；盘里读到窗口类条目 ⇒ 上提到盘后一位。
   **读路径只降级，不丢用户的卡。**
2. **折叠只有一份判据**：不新增收起表、不新增「盘专用」展开状态。
3. **不存坐标、不存列数**：盘的布局就是小卡排，列数现算。
4. **关闭容器 ≠ 移出成员。**
5. **空盘即无**：写出时解散（不是读时悄悄删）。
6. **key 稳定**：改名、换槽、收起都不换 key。

### 3.5 否掉的形状

| 形状 | 为什么不行 |
|---|---|
| 收起 ＝ 一颗「文件夹格」 | 收起改变骨架（同一个对象两种形状）；一格 44px 放不下卡头三颗按钮 ⇒ 盘丢了把手；还得给盘开「不参与列均分」的例外 |
| 溢出收拢（超出首行收进 `+n`） | 成员由「第几行」决定：槽宽一变成员就变（位置承载语义） |
| 扁平分组头（往列表里插一个 header） | 成员靠相邻推出，任何一次拖动／追加都静默改组，数据里看不出错 |
| 先建空盘、再从画廊拖入 | 先欠一个没有内容的承诺，再欠 n 次拖拽 |
| 盘内列数可配／画布式摆放 | 第二条布局真相：顺序就不再是唯一语义 |
| 盘里放窗口／派生卡 | 第二个槽 |
| 命名布局／工作区切换 | 那是「整槽换一套内容」，与收纳正交；若将来要做，盘是它下一层 |

### 3.6 落地要点

- `core/views/dock.ts`：联合加一项；`dockKey`；`canonicalDockEntries` 两趟（摊平／上提 ＋ 跨层去重）；
  新增 `findDock(cards, key) → { list, index }` —— **「按 key 找条目」只有这一份**，
  `findSide`／`closeCard`／`moveCard`／`addTile`／`insertShortcut` 全走它。
- `core/storage/prefs.ts`：左右槽去重时摊平一层（同一个快捷卡不该同时躺在两槽的盘里）。
  设备状态没有版本号 ⇒ 纯增量；旧版本读到盘会丢掉它，不做兼容。
- `app/wiring/docks.ts`：渲染走共用 band；三个落点（盘头／盘 body／槽）同一个载荷；
  每次写入后 `dissolveIfEmpty`（空盘不落盘）。
- `ui/dock/`：盘就是一个 `DockCard`（body 换成 band），不新增外壳。
- `styles/slots.css`：`.dock-tray-body` 一条规则（复用同一组 token）。

### 3.7 断言

1. 盘收起后**高度与张数无关**（一行卡头），三颗按钮与普通卡同列。
2. 盘内小卡的右缘 ＝ 盘内容盒右缘（A18 从「槽内容盒」改成「所在容器内容盒」）。
3. ✕ 解散后小卡的**数量与顺序都不变**。
4. 空盘不落盘、不画。
5. 读到嵌套盘／盘里读到窗口卡 ⇒ 摊平或上提，**一张都不丢**。

### 3.8 代价登记

- 收纳的定义就是**多一次点击**：盘里的动作要两下（展开 ＋ 执行）。所以热的手势留在裸排、
  冷的才进盘 —— 这是用法约定，不是缺陷。
- 展开态多一行卡头（28px）；盘只在 ≥2 行小卡时净赚。
- 盘的 body 对齐基准从「槽内容盒」变成「卡内容盒」：这是 A18 唯一需要改口径的地方。
- 盘是设备状态：不跨设备、不进搜索、不能被引用 —— 「家具不装进库」的必然结果。

## 4 有数据的是块，纯动作是命令，现算的是派生卡

> **这个卡片的配置/数据要不要跟着库走、要不要能出现在正文或被引用？**
> 要 → 块（窗口卡/露面渲染它）；不要 → 命令或宿主单例。

「接受一组块 id、渲染一组行」这类**清单**按内容走：建一个块，正文里放块引。
不为一个 UI 概念在库里造实体——造出来的那个块会漏进搜索、⌘O、统计这套通用机制，
而它本身不是内容。这是「收藏」从块退场时换来的判据，下一个想当 widget 的数据
概念先过这一关。

新 widget（如果将来有）＝宿主侧加一张卡：目录进派生卡闭集（画廊、渲染、解析共用一份），
数据要么现算、要么进设备状态——**不再走块类型声明**。

## 5 脚本与插件

**脚本 ＝ 命令/插件，不是卡片里的一段内联 JS。**

- 卡片只存「调用哪条命令 ＋ 参数」；代码住在插件模块里。
- 脚本通过受管门面读 query/index、调命令、走事务写；不碰裸存储、Node 内建、密钥、单写通道旁路。
- 禁用插件 ⇒ 撤销注册；卡片降级成占位，位置不 reflow，数据保留。

---

## 6 表格：View 类型，不是 Widget

表格是**视图块**（source ＋ columns ＋ sort），行＝源里的块、行身份是块 id。
排序/筛选/分组/列宽/滚动/选中是视图状态，外挂、按露面实例键控，不进 KB。

## 7 宿主与插件的分工

| 归宿主 | 归插件 |
|---|---|
| 槽的顺序、流式布局、拖拽、移除 | — |
| 大卡壳（头／折叠／单卡／关闭）；小卡格（列宽均分） | — |
| 数据读取（query／index）、事务订阅刷新 | 声明数据源、格式化 |
| 命令执行、权限、undo | 交互要调的命令 |
| 主题 token、UI 原语 | 用原语搭 body，不写裸色 |
| 生命周期、焦点、滚动 | renderer 的内部状态／定时器 |

**插件不拥有卡壳、不拥有位置、不直接写 KB。** 这三条守住，插件画什么都拆不掉应用。

**卡头只放「这张卡」的控件**：把手标（左）／收起／单卡／关闭（右），**每张卡同构**——卡头是**跨卡扫视**的区域。
作用于内容的动作长在 body 里、贴着它作用的东西（日历的「回到本月」＝点月份标签）。
**静置只剩「上下文」**：按钮淡出、永远占位，悬停这张卡／键盘聚焦时进场；显形前后列与右缘不动
（A24 的列不变量在显形时刻成立），没有「半颗按钮透明仍占位」的虚边（那条虚边是早先
`✕` 用 `opacity: 0` 的实测坑）。静置时卡头若显示文字，唯一职责是说出**正文看不出的上下文**
（窗口卡的块路径、盘的小卡数）——正文自己报得出名字的卡（日历／归属树／反链／回收站／
检视／搜索）静置只剩把手标（grip），名字随 hover 进场：让「日历」压在月份导航上，
等于在卡顶叠两套对齐语法的头，名字读作漂浮的碎字。没有字的把手条由 grip 站出来——
把手条本来就是把手。**收起的卡＝它的头**，全键与标题常驻。
卡头不能整条隐藏或浮在内容上：把手会压住正文第一行（日历的月份导航、窗口卡的首行
会被隐形把手截走点击）。

## 8 退化与生命周期

| 情况 | `cmd:` 小卡 | 窗口卡 | 派生卡 |
|---|---|---|---|
| 命令／块不可用 | 占位瓦片 | 块缺失不渲染 | 不渲染 |
| 插件卸载 | 占位 | — | — |
| 从槽移除 | 移除条目（无块） | 移出 `cards`，块不动 | 移出 `cards` |
| 再打开 | 画廊「动作」 | 搜索／Shift+点 | 画廊「系统」 |

`collapsedCards`／`solo` 只对 large 有意义；small 没有折叠／单卡，只有移除。
位置稳定优先于可用性过滤——不可用不要 reflow。快捷卡的目标块被删时同样保留这一格：
置灰、短标签收起、悬停说明「块已删除」，点它给一句提示而不是静默打开一个空处；
块从回收站恢复后，这一格自己活回来（名字每次重画现算，不存快照）。

## 9 当前状态（诚实地分开）

**已落地：**

- **收纳盘**（§3）：小卡收进一张卡（卡头是把手、body 是小卡排）。只收叶子、不嵌套、空盘自动解散。
  「按 key 找条目」只有一份 `findDock`（顶层与盘内都找得到，`closeCard`／`moveCard`／
  `addTile`／`insertShortcut`／`findSide` 全走它）；槽与盘共用同一份 band 渲染与列数函数；
  收起复用 `collapsedCards` ＋ `isCardCollapsed`，不新增收起表。读写两头守「只许叶子」：
  写入口只放 `cmd`／`shortcut` 进盘；读入口摊平嵌套盘、上提窗口类，一张不丢。
- `cards` 支持 `cmd:<命令名>`；同一个命令可同时出现在两槽。
- 小卡高度固定 44、按列均分（列数 ＝ min(放得下几列, 实际几张)）；可加、可移、同排拖序；命令不可用时保留占位。
- 窗口卡：拖入＝钉住常驻，Shift+点＝临时打开；非 pin 的窗口重启即清。
- 派生卡闭集（`DERIVED_CARDS` 一份目录：画廊、渲染分支、旧字节解析共用）。
- **快捷小卡**：槽里加一颗指向某个块的常驻入口；与窗口卡并存，重启不会被当作临时窗口清掉。
- **编辑岛标记**：块底的挂载区与露面行的身体都标 `data-edit-island`。
  父编辑器靠它回答「焦点现在是不是在别人的地盘上」——按类名判会让每多一种编辑岛就静默判错一次。
- 断言：`A18`（列均分／整排右缘与大卡对齐／大卡整行）＋ `A18t`（**盘内容盒**右缘＝
  A18「所在容器」口径的盘那一半；收起高度与张数无关；三颗按钮与普通卡同列）＋
  小卡点击走命令面／加／移／拖序、**未知插入类型不降级**、**收藏整套退场**（命令面不认、画廊没有）＋
  收纳盘交互（建盘在原位、一次收完、盘内排序、盘头收进去、拖槽移出来、
  ✕ 解散不带走成员、空盘自动解散、重命名不换 key）＋
  读路径（嵌套盘摊平／窗口类上提一张不丢，单元测试钉住）。

**曾做过又拆掉的（留痕，防重蹈）：**

- **组件块**（块类型声明 `widget` 槽卡 ＋ 两档高度 `:focus-within` 切档）：唯一消费者是收藏卡；
  收藏退场后机制不可达，整套拆除。将来 widget＝宿主侧卡（§4），不再走块类型声明。
- **收藏卡**（`_items` 有序引用、拖入/选择/拖序/× 只摘引用）：清单按内容走（块＋块引），
  不为收藏在库里造块——造出来的块会漏进通用机制，而它不是内容。

**明确不做：**

- **在卡里新建条目**：内容应该生在它真实的位置再被收进来；
  在卡里新建等于让「这一块住在哪」由「谁收藏了它」决定——那是又一根轴。
- **为一张卡造一个块**：同一条判据的另一半，收藏已经交过这笔学费。

## 10 三条不变量

1. **槽只存位置**：`cards` 是 id 列表，不是数据副本。
2. **块是真相**：同一块在正文/槽/查询里编辑，共享 store 与 undo；视图状态外挂。
3. **插件不拥有 chrome**：卡壳、位置、写通道归宿主；插件只画 body、只调命令。
