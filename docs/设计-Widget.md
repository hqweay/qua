# Widget：槽里的卡

> 这份只回答一件事：**侧槽里的一个格子是什么、它从哪来、能长成什么样。**
> 它不替代 `模型-一切皆块.md`；相反，它把「槽」这一层接到那套模型上。

---

## 0 一句话

> **槽里的卡只有两种：窗口（渲染某个块）与家具（宿主现算）。Widget 指后者。**
> 一块数据仍然住在块里；一条动作仍然是一条命令；槽只负责「把谁放在哪」。

历史上 widget 曾是「一种块类型在槽里的露面」（块类型声明里有一格 `widget`）。
那条路随「收藏」的退场一起拆掉了：它唯一的意义是为一张卡在库里造一个块，
而「块与 widget 解耦」之后，**widget 从此是宿主侧的东西**——像派生卡那样住在装配层，
不经过块模型。块类型声明回答的只有「这一行的骨架是什么」。

| 轴 | 回答什么 | 例子 |
|---|---|---|
| **Source（真相）** | 数据是什么 | 一棵块树、一个查询 |
| **View（渲染）** | 怎么画 | 大纲、表格、看板、日历 |
| **Surface（露面）** | 出现在哪 | 正文一行、中心全屏、槽里大卡、小卡 |

---

## 1 一条列表，三种条目

槽的设备状态只有一条有序列表：

```ts
type DockEntry =
  | { kind: 'block'; block: string }          // 一个块的窗口（拖进来或打开）
  | { kind: 'derived'; card: DerivedCardId }  // 宿主现算的派生卡
  | { kind: 'cmd'; command: string }          // 一个命令的小卡

interface DockSlotPrefs {
  open: boolean
  width: number | null
  cards: DockEntry[]   // 有序
}
```

**种类由 `kind` 说，不由字符串形状猜**：写入口按 `kind` 构造、渲染按 `kind` 穷举。
加一种来源＝编译期错误，而不是「那种卡不出现」。

| 条目 | 尺寸 | 有没有块 | 身份（`dockKey`） |
|---|---|---|---|
| `block`（窗口卡） | large | 有 | 块 id |
| `derived`（`inspect`／`belongs`／`backrefs`／`trash`／`calendar`） | large | 没有 | 派生卡 id |
| `cmd` | small | 没有 | `cmd:<命令名>` |

`cmd` 不是块，所以**同一个命令可以同时出现在左右两槽**；块仍然全局最多一张窗口
（同一个块不会在两边各开一份）。DOM 的 `data-card-id`、收起／单卡表、拖拽载荷
仍用扁平 key——换一串会让用户已折叠／已单卡的卡静默复位。

**窗口卡不挑块**：槽是视口，不是类型的分派器。拖任意块进槽＝一张钉住的窗口卡，
Shift+点＝临时打开（重启即清，除非 pin）。

---

## 2 两种尺寸，一个流

- **small**：44×44 固定，图标（或自定义小视觉），点击＝命令。不随槽宽拉伸。
- **large**：占满整行，用现有卡壳（头／折叠／单卡／关闭／拖拽），body 由渲染器决定。

槽内容是一个 `flex-wrap` 流：小卡横排、自动换行；大卡占满一行。顺序仍是一条线
（DOM 顺序 = `cards` 顺序）；换行只是排版，不是第二层列表。

默认左槽：四个快捷（回到今日／新建页面／命令面板／前一天）＋ 日历 ＋ 归属树；
右槽：检视卡 ＋ 反链。

---

## 3 有数据的是块，纯动作是命令，现算的是派生卡

> **这个卡片的配置/数据要不要跟着库走、要不要能出现在正文或被引用？**
> 要 → 块（窗口卡/露面渲染它）；不要 → 命令或宿主单例。

「接受一组块 id、渲染一组行」这类**清单**按内容走：建一个块，正文里放块引。
不为一个 UI 概念在库里造实体——造出来的那个块会漏进搜索、⌘O、统计这套通用机制，
而它本身不是内容。这是「收藏」从块退场时换来的判据，下一个想当 widget 的数据
概念先过这一关。

新 widget（如果将来有）＝宿主侧加一张卡：目录进派生卡闭集（画廊、渲染、解析共用一份），
数据要么现算、要么进设备状态——**不再走块类型声明**。

---

## 4 脚本与插件

**脚本 ＝ 命令/插件，不是卡片里的一段内联 JS。**

- 卡片只存「调用哪条命令 ＋ 参数」；代码住在插件模块里。
- 脚本通过受管门面读 query/index、调命令、走事务写；不碰裸存储、Node 内建、密钥、单写通道旁路。
- 禁用插件 ⇒ 撤销注册；卡片降级成占位，位置不 reflow，数据保留。

---

## 5 表格：View 类型，不是 Widget

表格是**视图块**（source ＋ columns ＋ sort），行＝源里的块、行身份是块 id。
排序/筛选/分组/列宽/滚动/选中是视图状态，外挂、按露面实例键控，不进 KB。

---

## 6 宿主与插件的分工

| 归宿主 | 归插件 |
|---|---|
| 槽的顺序、流式布局、拖拽、移除 | — |
| 大卡壳（头／折叠／单卡／关闭）；小卡 44px 格 | — |
| 数据读取（query／index）、事务订阅刷新 | 声明数据源、格式化 |
| 命令执行、权限、undo | 交互要调的命令 |
| 主题 token、UI 原语 | 用原语搭 body，不写裸色 |
| 生命周期、焦点、滚动 | renderer 的内部状态／定时器 |

**插件不拥有卡壳、不拥有位置、不直接写 KB。** 这三条守住，插件画什么都拆不掉应用。

**卡头只放「这张卡」的控件**：收起（左）／单卡／关闭（右），**每张卡同构**——卡头是**跨卡扫视**的区域。
作用于内容的动作长在 body 里、贴着它作用的东西（日历的「回到本月」＝点月份标签）。
关闭常驻但低对比，不用 `opacity: 0` 假隐藏——透明仍占位，会在每张卡右边留一条虚边。

## 7 退化与生命周期

| 情况 | `cmd:` 小卡 | 窗口卡 | 派生卡 |
|---|---|---|---|
| 命令／块不可用 | 占位瓦片 | 块缺失不渲染 | 不渲染 |
| 插件卸载 | 占位 | — | — |
| 从槽移除 | 移除条目（无块） | 移出 `cards`，块不动 | 移出 `cards` |
| 再打开 | 画廊「动作」 | 搜索／Shift+点 | 画廊「系统」 |

`collapsedCards`／`solo` 只对 large 有意义；small 没有折叠／单卡，只有移除。
位置稳定优先于可用性过滤——不可用不要 reflow。

## 8 当前状态（诚实地分开）

**已落地：**

- `cards` 支持 `cmd:<命令名>`；同一个命令可同时出现在两槽。
- 小卡 44×44、流式换行；可加、可移、同排拖序；命令不可用时保留占位。
- 窗口卡：拖入＝钉住常驻，Shift+点＝临时打开；非 pin 的窗口重启即清。
- 派生卡闭集（`DERIVED_CARDS` 一份目录：画廊、渲染分支、旧字节解析共用）。
- **编辑岛标记**：块底的挂载区与露面行的身体都标 `data-edit-island`。
  父编辑器靠它回答「焦点现在是不是在别人的地盘上」——按类名判会让每多一种编辑岛就静默判错一次。
- 断言：`A18`（44px／顶对齐／大卡整行）、小卡点击走命令面／加／移／拖序、
  **未知插入类型不降级**、**收藏整套退场**（命令面不认、画廊没有）。

**曾做过又拆掉的（留痕，防重蹈）：**

- **组件块**（块类型声明 `widget` 槽卡 ＋ 两档高度 `:focus-within` 切档）：唯一消费者是收藏卡；
  收藏退场后机制不可达，整套拆除。将来 widget＝宿主侧卡（§3），不再走块类型声明。
- **收藏卡**（`_items` 有序引用、拖入/选择/拖序/× 只摘引用）：清单按内容走（块＋块引），
  不为收藏在库里造块——造出来的块会漏进通用机制，而它不是内容。

**明确不做：**

- **在卡里新建条目**：内容应该生在它真实的位置再被收进来；
  在卡里新建等于让「这一块住在哪」由「谁收藏了它」决定——那是又一根轴。
- **为一张卡造一个块**：同一条判据的另一半，收藏已经交过这笔学费。

---

## 9 三条不变量

1. **槽只存位置**：`cards` 是 id 列表，不是数据副本。
2. **块是真相**：同一块在正文/槽/查询里编辑，共享 store 与 undo；视图状态外挂。
3. **插件不拥有 chrome**：卡壳、位置、写通道归宿主；插件只画 body、只调命令。
