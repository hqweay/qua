# 模型的地基：一切皆块

> **动模型之前先读这份。** 这里不讲实现细节，只讲**判据**与**为什么**——
> 判据才是离开这份文档还能用的东西。代码里每一处「看起来绕」的地方，多半能在这里找到理由。

---

## 0 一句话

> **库里只有一个东西：块。其他一切（页、日记、标签、视图、面板）都是块的某种「角色」或「渲染」。**

**不存在的实体**（这是最容易记错的部分）：

| 不是实体 | 它是什么 |
|---|---|
| **页** | 一个带 `page` **角色**的块；页名就是那个块的正文 |
| **日记** | 一个带 `journal` **角色**的块；内容是日期（属性 `_date`），全局一天一个，**只读** |
| **标签** | 「打标签」＝一条**指向边** ＋ 一次 schema 引用 |
| **视图**（大纲／表格／看板…） | 对**一棵真实树**的一次**渲染** |
| **文件夹** | 不存在——层级就是真实父子（`children` ／ `parent` 链） |
| **侧栏／面板** | 一个槽，里面是**一列块** |

代码里的对应事实：

```ts
// core/model.ts
interface Block {
  id, text, children
  roles?: Role[]                           // 角色（不是属性；可兼位，顺序无语义）
  props?: Record<string, unknown>          // 属性；键＝字段定义块的 id（系统结构位以 _ 开头）
  collapsed?, todo?                        // 视图状态（原型里随模型存，接内核后应外挂）
}

// core/storage/shape.ts
interface Workspace {
  blocks: Block[]        // ★ 一片森林，不是 pages 数组
  activeId: string       // 「当前对象」的块 id
  marks, atoms, prefs …
}
```

- **页名 = 块正文**（`text`），**图标 = `props._icon`**
- 系统属性一律 **`_` 开头**：`_type`／`_tags`／`_icon`／`_date` …

## 1 三条判据

拿这三条就能判断一个设计对不对。

### 判据 ①「是不是某种东西」用**角色**，「有什么数据」用**属性**

- **角色（`roles`）**：这块在系统里**担任什么机制位**（`page`／`journal`／`tag`／`schema`…）。是块上的一等声明。
  准入的一条硬判据：**角色是读路径的入口**——每种角色都得有代码按它把块找出来。
  只为「给渲染层挑个专用渲染器」而加的角色不合格：那是外观问题，归类型与 `props`。
- **一个块可以同时担任多个角色**（例：既是标签、又能当页打开）。判定只走 `hasRole(block, role)`；
  **数组顺序不承载语义**，不要按位置取「主角色」。
- **属性（`props`）**：这块**有什么数据**。两种键，别混：
  - **系统结构位**以 **`_` 开头**（`_type`／`_icon`／`_date`）——没有定义块，形状由模型代码解释，
    也不进属性面板（`ownFieldIds` 按这个前缀过滤）。
  - **普通字段**的键是**字段定义块的块 id**——不是名字。定义块自己承载显示名（正文＝label），
    ⇒ 改显示名不动任何值。**别把 `ns/name` 当键写**：命名空间在属性上还没有载体，
    要落时它属于定义块的**别名**，且必须是**另一张索引**（字段显示名允许重名、不进内容地址空间）。
- **⇒ `_role` 不存在。`props.role` 也是错的。**

**怎么错的**：用 `props.role` 表达「这页是页」两头都不对——`_` 前缀要求它是系统属性，
而角色根本不是属性。**判据要落到类型上，不能只落到注释上。**

### 判据 ② 数据层只回答「是什么」，随时变的东西归**查询**或**视图配置**

三层要分清：

| 层 | 回答 | 例子 |
|---|---|---|
| **属性** | 这个东西**是什么** | 图标、日期、标签 |
| **视图配置** | **怎么显示** | 排序、筛选、分组、范围 |
| **视图状态** | **此刻怎样**（外挂，不入库） | 滚动、折叠、宽度 |

**怎么错的**：曾想给块加 `indexScope: all/local/none` 控制「要不要被搜到」。
但**如果是为了检索，完全可以通过一个查询条件达到**——检索意图属于**当次查询**，
不属于数据。写进数据就要背迁移、继承、同步。

> 推论：**不要给块加「某种检索／显示偏好」字段。** 这类需求一律落到查询条件或视图配置。

### 判据 ③ 同一个块，在哪儿都该长一个样（一源多视）

- 一个视图块出现在左槽、中心槽、正文里 → **一份数据、多份视图实例**
- 一个块在左槽列表里和在正文里 → **同一个渲染器**
- **⇒ 渲染按「块的角色／类型」分派，不按「它在哪个容器里」分派**

**怎么错的**：左槽曾写了个 `<nav id="pages">` 专门装页面按钮。
**「我们的概念里一切皆块」**——修法是删掉容器，改成 `renderBlock(block, ctx)` 按角色画。

### 判据 ④ 位置属于内容，名字属于身份

**「有身份的块」**＝ 带 `tag`／`schema`／`journal` 角色的块。它们**不参与组织**，必须在顶层。
`page` **不在这条里**——页是容器，它就是被组织的（往页里放东西）。

判据是**读路径**：所有找它们的代码都按 id（`allTags`／`findByAlias`／`tagMemberIds`／`tagsOf`），
或全森林扫描；标签层级走 `_parentTags`，**不是树位置**。

⇒ **位置对它们不承载任何信息。** 存着位置＝存一个没人读的字段，而所有树操作（缩进、拖拽、删除）
都会把它当货物搬走。三条实测过的 bug 都是这一个原因：

| 现象 | 原因 |
|---|---|
| 删祖先块，标签跟着消失 | 标签住在子树里 |
| `journal` 被缩进后，日记流里那一天不见了，而「物化今天」又造出一个同 id 的块 | 日记流读顶层数组，索引读整片森林 |
| 标签被拖进内容块的子树 | 移动路径不检查 |

三条不变量，**都只查被操作的那一块自己，不扫子树**：

| # | 不变量 | 维护点 | 成本 |
|---|---|---|---|
| **A 位置** | 身份块 `parent === null` | `addRole` ＋ `indentBlock`／`moveBlockTo`／`dropDrag` | O(1) × 4 |
| **B 正文** | 身份块的 `text` 是**名字**，内容写路径不许改它 | 一个 `canWriteText` 判据，喂给所有写路径 | O(1) |
| **C 存在** | 软删除 ＋ 同地址复活 | `removeBlock`／`ensureTag` | O(1) |

**A 的收益是删除变成零判断**：删一个内容块时，它的子树里**结构上不可能**有身份块
（否则那个身份块自己就违反 A）。所以「删一段话顺手删掉一个类」不是「被拦住」，是**不存在**。

**B 修的是一个静默 bug**：块首退格会把子块并进前块（`mergeIntoPrev`），这会**直接改写前块正文**。
前块是 `journal` ⇒ 日期块被写入字；前块是 `tag` ⇒ 标签名被静默改掉。一个判据修两处。

⚠️ **改名仍然允许**，而且引用不会断：边存的是 id，显示名渲染时现算
（`resolveRef` / `refTitle`）⇒ 改完所有 `#旧名` 当场显示新名字，一条边都不用改。

⚠️ **打字路径上不做任何校验**。撞名只在「改名」时查一次（地址索引是哈希，O(1)），
**不能在逐字符路径上查**——打「设计」，中间态「设」可能撞上另一个标签，输入法会被直接打死。

⚠️ **加角色不再是纯 append**：给一个嵌在内容块下的块加 `tag` 角色，必须先把整块（连子树）移到顶层。
这不是静默搬家——给一次点击，用户看见并同意，且可撤销。

## 2 交付层的形状（从判据推出来的）

### 2.1 槽里只能有块

```
槽（stack 容器）
 └ 块 ……（每块由 renderBlock 按角色／类型渲染）
```

**不许**出现：页面列表组件、入口条、"我的库"导航、任何"专门装某种东西"的容器。

### 2.2 堆叠与 tab 分属两层

| 层 | 负责 | 谁做 |
|---|---|---|
| **堆叠** | 槽／容器里 N 个块上下排：折叠、关闭、拖序 | **槽**（左右槽同构） |
| **tab** | 一个块内部把几种视图切成页签 | **块自己** |

**⇒ 槽层不许再加一层 tab**——会和块层重复，且让堆叠退化成一屏一块。

### 2.3 没有「入口条」

早期设计过「左右各一条常驻图标入口条」，已**整体作废**。理由三条：

1. 它的前提是「一个槽同一时刻只显示一样东西，点图标＝替换」——而槽内是**堆叠**，「替换」不存在了；
2. 它与「块自己实现 tab」**同一层重复**（都是"选看哪一样"，只是竖排图标版）；
3. 它本身就是一条**常驻导航外壳**，与「槽里没有导航外壳」冲突。

**现状**：`槽 ｜ 槽 ｜ 槽`，开关是每个槽抬头上的 `‹`／`›` 与 `⌘⌥1`／`⌘⌥2`。

## 3 代码落点

### 3.1 渲染分派

```ts
// ui/block-renderers.ts
renderBlock(block, ctx)   // 外观按**类型**、chrome 按角色；兜底永远有（不认识的块不会消失）
```

### 3.2 槽

```ts
// ui/dock.ts          槽：排一列块卡
// ui/dock-content.ts  左槽＝今日、右槽＝反链（都只是「往槽里排块」）
```

### 3.3 反链

```ts
// core/backrefs.ts  纯逻辑、零 DOM：扫指向边，按来源聚合
// 接内核后换成指向边索引，函数签名不变
```

### 3.4 分层（`arch-check [13]` 硬约束，**按目录判层**）

```
core/   model · ids · tree · journal · text · annotations · selection · undo   零 DOM
        when · bindings · backrefs · theme · ports · dispatch
        workspace · seed · msg
        commands/  decls（命令表）· registry（注册表）· index（上下文键）
        storage/   port（契约）· shape（落盘形状）· prefs · local-storage（唯一碰 localStorage）
view/   editor · block-dom · dom-text · editor-events · icons                  编辑器，零框架
ui/     dock · dock-content · block-renderers · chrome · badge · layers
        panels · backlinks · query-view                                        面板与外壳
app/    commands-impl（命令门面工厂）· handlers（处理器）                        实现层
main.ts 装配：只做 wiring
styles/ tokens（唯一定义处）· shell · slots · center · blocks · overlays · badge
```

**层由目录唯一决定**：`src/core/**` → core，`src/view/**` → view，`src/ui/**` → ui，
`src/app/**` → app，`electron/**` → host；`src/main.ts` 单列 app。
新增文件**自动落入所在层**，没有需要手工登记的第二张表。

**依赖方向单向**：`core ← view ← ui ← app ← host`。

> ⚠️ **view 不能 import ui。** 这不是洁癖：`block-dom.ts` 是**编辑器 DOM 契约的产地**，
> 它一旦回头依赖 `ui` 的组件，编辑器就被 UI 的形状绑架了。这条被断言拦下来过一次。

## 4 不要做的事

| 别做 | 为什么 |
|---|---|
| 给「页」建独立实体或独立组件 | 页是块 ＋ 角色（判据 ①） |
| 给块加「检索／显示偏好」字段 | 那是查询或视图配置（判据 ②） |
| 在槽里写专用列表容器 | 渲染按角色分派（判据 ③） |
| 在槽层加 tab | 与块层 tab 重复（§2.2） |
| 恢复入口条 | 已作废，理由见 §2.3 |
| 把 `role` 写成 `_role` 属性 | 角色不是属性（判据 ①） |
| **把 `tag`／`schema`／`journal` 当"可以住在任何地方的块"** | 它们**不占据位置**（判据 ④）：位置对它们不承载信息，而所有树操作都会把它当货物搬 |
| **在打字路径上校验标签重名** | 输入法中间态会撞名 ⇒ 打不进去。校验只在「改名」时（判据 ④ 的 B） |
| **给身份块加一个"必须在根"的守卫，只判"是不是根"** | 它拦不住"正在被移动"。约束要拦在**移动入口**上（判据 ④ 的 A） |

## 5 这些结论是怎么来的

留痕的目的是：看到一个「常识」时，知道它是**被验证过的**，还是**被想当然写下的**。

| 当时的想法 | 被什么推翻 |
|---|---|
| 块加 `indexScope` 控制检索 | 「如果是为了检索，完全可以通过一个查询条件达到」 |
| 代码块默认不索引 | 「代码块也应该默认能查，只有用户显式配置才不支持」 |
| 用标签 `#no-index` 标识 | 自证三条硬伤：标签自己被索引／循环／公开声明矛盾 |
| 左槽用 `<nav id="pages">` 装页面 | 「我们的概念里一切皆块」 |
| 常驻图标入口条 | 堆叠让「替换」这个动作消失，入口条失去意义 |
| `props.role` 表达角色 | 角色 ≠ 属性；系统属性才带 `_` 前缀 |
| `props` 的键写 `ns/kebab-name` | 键是**字段定义块的 id**：写名字就要在改名时迁移全库值；撞名靠 id 空间已经解决 |
| AI 隐私用块级标记 | 形态未定就设计接口 ＝ 过早抽象；且 AI 应当走查询通道 |
| 让 `tag`／`schema`／`journal` 住在任何块下面 | 位置对它们不承载信息（所有读路径按 id），却让所有树操作把它们当货物搬 ⇒ 删祖先带走标签、`journal` 被缩进后日记流看不见 |
| 给"有依赖者的块"做一张 `mustBeRoot` 角色名单 | 每加一个角色都要回答一次（＝名单），且只拦"是不是根"不拦"正在被移动" |
| 删子树时扫一遍、把身份块"提升"到顶层 | 把判断放回**出口**（删除是高频路径），每次删除都要遍历子树 |
| 给概念找临时替身，然后把替身当概念 | 「一组块」还没有载体时，命名容器块是个便宜的近似；但留着它，demo 的临时形状就会被当成产品概念读，还占着一个角色值 |
| 在打字时逐字符校验标签重名 | 输入法中间态会撞名 ⇒ 打不进去 |

## 6 与「其它派系」的分歧点

这几处是**有意这么定**的，改之前请先看理由：

- **不引入 `Page` 实体**：多数实现有独立的 page 表／对象。我们用「块 ＋ 角色」，
  于是「页里可以有子页」「页就是块」这类能力是**免费**的。
- **正文不是 contenteditable 套富文本框架**：自研块级 DOM ＋ 带 `blockId` 的区间锚点，
  于是「跨块选择」「原地编辑」「一源多视」在模型层就成立。
- **不把折叠／滚动／宽度写进库**：那是视图状态，外挂（判据 ②）。
