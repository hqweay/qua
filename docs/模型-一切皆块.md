# 模型的地基：一切皆块

> **动模型之前先读这份。** 这里不讲实现细节，只讲**判据**与**为什么**——
> 判据才是离开这份文档还能用的东西。代码里每一处「看起来绕」的地方，多半能在这里找到理由。

---

## 0 一句话

> **库里只有一个东西：块。其他一切（页、日记、标签、视图、面板）都是块的某种「身份」或「渲染」。**

**不存在的实体**（这是最容易记错的部分）：

| 不是实体 | 它是什么 |
|---|---|
| **页** | `_lists` 里有 `page` 的块；页名＝主别名（`_aliases[0]`，显示叶子），正文是描述 |
| **日记** | 一个带 `_date` 属性的块（身份由数据推出，不存标记）；全局一天一个，**只读** |
| **标签** | 「打标签」＝块上的一格**分类归属**（`props._tags`）；「标签」本身是 `_lists` 里有 `tag` 的块 |
| **视图**（大纲／表格／看板…） | 对**一棵真实树**的一次**渲染** |
| **文件夹** | 不存在——层级就是真实父子（`children` ／ `parent` 链） |
| **侧栏／面板** | 一个槽，里面是**一列块** |

代码里的对应事实：

```ts
// core/model.ts
interface Block {
  id, content, children                    // 内容槽只有四个：身份、内容、层级、属性袋
  props?: Record<string, unknown>          // 属性；键＝属性定义块的 id（系统结构位以 _ 开头）
                                           //   地址与露面就在里面：props._aliases / props._lists
}

// core/model.ts
type FoldState = Record<string, true>      // 折叠态：块 id → 收起（只记收起的）

// core/storage/shape.ts
interface Workspace {
  blocks: Block[]        // ★ 一片森林，不是 pages 数组
  activeId: string       // 「当前对象」的块 id
}
// 行内内容与可引用区间都住在块上（content / annos）：库里没有第二份扁平数组
```

- **设备状态不在库里**（`prefs` 自 2026-10-24，`folded` 自 2026-10-24 晚一步）：
  `prefs`（主题／槽宽／钉住／virtualize／badge）与折叠表都住在另一个键 `qua.device`，
  由 `storage/device.ts` 管理；换库不带走它们，库作废也不连累它们。

- **折叠态不在块上**：它会被树操作当货物搬走（合并／复制）、会进撤销栈、会跟着导出跑；
  所以它挂在**文档**（`Doc.folded`，编辑器装载的那份）与**设备**（`DeviceState.folded`，
  换库时清空——块 id 是库内的局部身份）上

- **页名 = 主别名**（`props._aliases[0]`，显示时取叶子），**正文 = 描述**，**图标 = `props._icon`**
- 系统属性一律 **`_` 开头**：`_type`／`_icon`／`_date`／`_aliases`／`_lists`／`_display` …
- **标签的归属只有一份**（`props._tags`，存标签块 id），但可以有**两种露面**：
  正文里的 `#名`（一枚占 1 格的 ref run，停在敲下的那一格）或不占正文的 chip。
  ⇒ 删掉正文里那枚**不摘标签**（分类不是内容）；摘标签是一次显式操作。

## 1 三条判据

拿这三条就能判断一个设计对不对。

### 判据 ①「它是谁」用**地址**，「在哪儿露面」用**列表**，「有什么数据」用**属性**

- **地址**：这块用什么名字被找到。住在 `props._aliases`（0..N，**首个是主名**，全局唯一，
  允许 `/` 分段、显示时取叶子）。**正文不在地址空间里**——正文是描述，改正文不会改名。
  读路径的准入判据是：地址必须能被 `findByAlias` 找到，且能出现在引用／反链的显示名里。
- **列表**：这块在哪个列表里**露面**。住在 `props._lists`（`page`／`tag`，可兼位、也可空）。
  页列表与标签列表只按它过滤（`hasList`）——「有名字」与「是页/标签」因此是两件独立的事。
- **其它身份由数据推出，不存标记**：有 `_date` 就是日记、有 `_kind` 就是属性定义、
  `_query` 是合法条件就是查询视图。判据是**同一件事只有一个答案**——再存一个标记就是第二份答案，
  而两份可以不一致（「有标记、没日期」的块没有任何合理读法）。
- **一个块可以同时进两个列表**（例：既是标签、又能当页打开）。判定只走 `hasList(block, list)`；
  **顺序不承载语义**。要「这一行有没有身份」（地址 ∪ 露面 ∪ 派生身份）用 `hasIdentity`，
  要读成外观身份（渲染、诊断）用 `identityTags`，只要列表集合用 `listsOf`。
- **地址与列表住在属性袋里**，但它们**不是普通字段**：它们是系统结构位（`_` 前缀），
  没有定义块、形状由模型代码解释、不进属性面板。放在属性袋里的理由是纯工程账：
  块的内容槽只有 `id`／`content`／`children`／`props` 四个，整份拷贝一个块时只需要浅拷 `props`，
  身份就跟着走了——否则每加一个树操作（复制页、复制标签）都得记得多搬一个字段，
  漏掉时**不报错**，只是复制出来的页悄悄变成一块长得像页的普通块。
- **`_display`（`alias`／`text`）只决定这一行自己的头显示什么**。它跟地址一起存，
  但不是「视图状态」（滚动／折叠／宽度）：它选的是「这一行拿名字还是拿描述当标题」。
  引用／反链**不跟它走**——否则同一个块在别处会有两个名字，而地址只有一个。
- **属性（`props`）**：这块**有什么数据**。三个词别混：**属性**＝那个全局定义（有名字、有 kind、
  可被多处引用）；**标签属性**＝某个标签**声明**了哪些属性可用（**不向成员继承**：没打这个标签的块
  一个都没有）；**块属性**＝这个块自己有哪些属性的值。下面两种键，别混：
  - **系统结构位**以 **`_` 开头**（`_type`／`_icon`／`_date`／`_aliases`／`_lists`／`_display`）——
    没有定义块，形状由模型代码解释，也不进属性面板（`ownFieldIds` 按这个前缀过滤）。
    例外只有一处：`_uiPosition` 写在**定义块**上，说的是「这条属性在哪儿被编辑」
    （`block-left` 归块左侧的 gutter、`panel` 归右侧面板，缺省 `panel`）。两处互斥——
    同一个值有两个编辑面，就会出现「一边改了、另一边没跟上」。
  - **块属性**的键是**属性定义块的块 id**——不是名字。定义块自己承载显示名（正文＝label），
    ⇒ 改显示名不动任何值。**别把 `ns/name` 当键写**：命名空间在属性上还没有载体，
    要落时它属于定义块的**别名**，且必须是**另一张索引**（属性显示名允许重名、不进内容地址空间）。
- **⇒ 块上没有 `role`／`roles` 字段；`props._roles` 是旧键，形状校验直接判 corrupt。**

**怎么错的**：用一个单值 `role` 或一个 `_roles` 数组同时表达「叫什么」和「在哪个列表露面」，
会让两件事绑死：改名字变成改身份、进页列表与进标签列表变成互斥转换，而且每加一个「整块拷贝」的路径
都要手工搬它一遍。判据要落到**唯一入口**上，不能只落到注释上：地址读写走
`aliasesOf`／`primaryAliasOf`／`addAlias`／`setPrimaryAlias`，露面走
`hasList`／`listsOf`／`addList`／`removeList`，裸读由静态断言拦住。

### 判据 ② 数据层只回答「是什么」，随时变的东西归**查询**或**视图配置**

三层要分清：

| 层 | 回答 | 例子 |
|---|---|---|
| **属性** | 这个东西**是什么** | 图标、日期、标签 |
| **视图配置** | **怎么显示** | 排序、筛选、分组、范围 |
| **视图状态** | **此刻怎样** | 滚动、折叠、宽度 |

⚠️ 视图状态**不挂在块上**。折叠态住在文档／设备那一层（`Doc.folded`／`DeviceState.folded`，
只记「收起的」块 id），字段（`Block`）里什么都没有。挂块上会付三笔账：
树操作会把它当货物搬（合并／复制）、`⌘Z` 会把折叠撤回去、导出会带上「我上次把哪行收起来了」。

**怎么错的**：曾想给块加 `indexScope: all/local/none` 控制「要不要被搜到」。
但**如果是为了检索，完全可以通过一个查询条件达到**——检索意图属于**当次查询**，
不属于数据。写进数据就要背迁移、继承、同步。

> 推论：**不要给块加「某种检索／显示偏好」字段。** 这类需求一律落到查询条件或视图配置。

### 判据 ③ 同一个块，在哪儿都该长一个样（一源多视）

- 一个视图块出现在左槽、中心槽、正文里 → **一份数据、多份视图实例**
- 一个块在左槽列表里和在正文里 → **同一个渲染器**
- **⇒ 渲染按「块的类型」分派、chrome 按「身份标记（`identityTags`）」**，不按「它在哪个容器里」分派**

**怎么错的**：左槽曾写了个 `<nav id="pages">` 专门装页面按钮。
**「我们的概念里一切皆块」**——修法是删掉容器，改成 `renderBlock(block, ctx)` 按类型画。

### 判据 ④ 位置属于内容，地址属于块

**创建时默认落在顶层的块**＝ 进了 `tag` 列表、或带 `_date`／`_kind`／`_query`（日记／定义／查询）的块。
它们**不参与组织**，创建时物化在顶层；此后移动或加露面**不再强制移出**（软删兜底，可恢复）。
`page` **不在这条里**——页是容器，它就是被组织的（往页里放东西）。

判据是**读路径**：所有找它们的代码都按 id（`allTags`／`findByAlias`／`tagMemberIds`／`tagsOf`），
或全森林扫描；标签层级走 `_belongsTo`（0..N 的归属边，任何块都能配），**不是树位置**。

⇒ **位置对它们不承载任何信息。** 存着位置＝存一个没人读的字段，而所有树操作（缩进、拖拽、删除）
都会把它当货物搬走。三条实测过的 bug 都是这一个原因：

| 现象 | 原因 |
|---|---|
| 删祖先块，标签跟着消失 | 标签住在子树里 |
| `journal` 被缩进后，日记流里那一天不见了，而「物化今天」又造出一个同 id 的块 | 日记流读顶层数组，索引读整片森林 |
| 标签被拖进内容块的子树 | 移动路径不检查 |

三条不变量，**都只查被操作的那一块自己，不扫子树**：

| # | 不变量 | 维护点 | 成本 |
|---|---|---|---|
| **A 位置** | 必须顶层的块 `parent === null` | `addList` ＋ `indentBlock`／`moveBlockTo`／`dropDrag` | O(1) × 4 |
| **B 地址** | 正文写路径**一个字节都碰不到 `_aliases`** | 一个 `canWriteText` 判据（journal／定义／查询的正文不可写） | O(1) |
| **C 存在** | 软删除 ＋ 同地址复活 | `removeBlock`／`ensureTag` | O(1) |

**A 的收益是删除变成零判断**：删一个内容块时，它的子树里**结构上不可能**有必须顶层的块
（否则那个块自己就违反 A）。所以「删一段话顺手删掉一个类」不是「被拦住」，是**不存在**。

**B 修的是一个静默 bug**：块首退格会把子块并进前块（`mergeIntoPrev`），这会**直接改写前块正文**。
正文是描述，改写它不是改名——但旧实现让正文兼作地址，于是 `journal` 被写入字、标签名被静默改掉。
现在地址只住在 `_aliases`，正文写路径碰不到它；`journal`／定义／查询的正文仍整体不可写。

⚠️ **改名仍然允许**，而且引用不会断：边存的是 id，显示名渲染时现算
（`resolveRef` / `refTitle`）⇒ 改完所有 `#旧名` 当场显示新名字，一条边都不用改。

⚠️ **打字路径上不做任何校验**。撞名只在「改名／加别名」时查一次（地址索引是哈希，O(1)），
**不能在逐字符路径上查**——打「设计」，中间态「设」可能撞上另一个标签，输入法会被直接打死。

⚠️ **加 tag 露面不再是纯 append**：给一个嵌在内容块下的块加 `tag` 露面，必须先把整块（连子树）移到顶层。
这不是静默搬家——给一次点击，用户看见并同意，且可撤销。

## 2 交付层的形状（从判据推出来的）

### 2.1 槽里只能有块

```
槽（stack 容器）
 └ 块 ……（每块由 renderBlock 按类型／身份标记渲染）
```

**不许**出现：页面列表组件、入口条、"我的库"导航、任何"专门装某种东西"的容器。

### 2.2 堆叠与 tab 分属两层

| 层 | 负责 | 谁做 |
|---|---|---|
| **堆叠** | 槽／容器里 N 个块上下排：折叠、关闭、拖序 | **槽**（左右槽同构） |
| **tab** | 一个块内部把几种视图切成页签 | **块自己** |

**⇒ 槽层不许再加一层 tab**——会和块层重复，且让堆叠退化成一屏一块。

### 2.3 没有「入口条」

早期设计过「左右各一条常驻图标入口条」，已**整体作废**。理由三条：

1. 它的前提是「一个槽同一时刻只显示一样东西，点图标＝替换」——而槽内是**堆叠**，「替换」不存在了；
2. 它与「块自己实现 tab」**同一层重复**（都是"选看哪一样"，只是竖排图标版）；
3. 它本身就是一条**常驻导航外壳**，与「槽里没有导航外壳」冲突。

**现状**：`槽 ｜ 槽 ｜ 槽`，开关是每个槽抬头上的 `‹`／`›` 与 `⌘⌥1`／`⌘⌥2`。

## 3 代码落点

### 3.1 渲染分派

```ts
// ui/block-renderers.ts
renderBlock(block, ctx)   // 外观按**类型**、chrome 按身份标记（identityTags）；兜底永远有（不认识的块不会消失）
```

### 3.2 槽

```ts
// ui/dock.ts          槽：排一列块卡
// ui/dock-content.ts  左槽＝今日、右槽＝反链（都只是「往槽里排块」）
```

### 3.3 反链

```ts
// core/backrefs.ts  纯逻辑、零 DOM：扫指向边，按来源聚合
// 接内核后换成指向边索引，函数签名不变
```

### 3.4 分层（`arch-check [13]` 硬约束，**按目录判层**）

```
core/   model · runs · ids · tree · journal · selection · undo                  零 DOM
        when · bindings · backrefs · theme · ports · dispatch
        workspace · seed · msg
        commands/  decls（命令表）· registry（注册表）· index（上下文键）
        storage/   port（契约）· shape（落盘形状）· prefs · device（设备偏好）· local-storage（唯一碰 localStorage）
view/   editor · block-dom · dom-text · editor-events · icons                  编辑器，零框架
ui/     dock · dock-content · block-renderers · chrome · badge · layers
        panels · backlinks · query-view                                        面板与外壳
app/    commands-impl（命令门面工厂）· handlers（处理器）                        实现层
main.ts 装配：只做 wiring
styles/ tokens（唯一定义处）· shell · slots · center · blocks · overlays · badge
```

**层由目录唯一决定**：`src/core/**` → core，`src/view/**` → view，`src/ui/**` → ui，
`src/app/**` → app，`electron/**` → host；`src/main.ts` 单列 app。
新增文件**自动落入所在层**，没有需要手工登记的第二张表。

**依赖方向单向**：`core ← view ← ui ← app ← host`。

> ⚠️ **view 不能 import ui。** 这不是洁癖：`block-dom.ts` 是**编辑器 DOM 契约的产地**，
> 它一旦回头依赖 `ui` 的组件，编辑器就被 UI 的形状绑架了。这条被断言拦下来过一次。

## 4 不要做的事

| 别做 | 为什么 |
|---|---|
| 给「页」建独立实体或独立组件 | 页是块 ＋ `page` 露面（判据 ①） |
| 给块加「检索／显示偏好」字段 | 那是查询或视图配置（判据 ②） |
| 在槽里写专用列表容器 | 渲染按类型／身份标记分派（判据 ③） |
| 在槽层加 tab | 与块层 tab 重复（§2.2） |
| 恢复入口条 | 已作废，理由见 §2.3 |
| 用一个单值 `role` 字段表达多种露面 | 露面可兼位；判定与读写只走 `hasList` 家族（判据 ①） |
| **把 `tag`／`schema`／`journal` 当"可以住在任何地方的块"** | 它们**不占据位置**（判据 ④）：位置对它们不承载信息，而所有树操作都会把它当货物搬 |
| **在打字路径上校验标签重名** | 输入法中间态会撞名 ⇒ 打不进去。校验只在「改名」时（判据 ④ 的 B） |
| **给必须顶层的块加一个"必须在根"的守卫，只判"是不是根"** | 它拦不住"正在被移动"。约束要拦在**移动入口**上（判据 ④ 的 A） |

## 5 这些结论是怎么来的

留痕的目的是：看到一个「常识」时，知道它是**被验证过的**，还是**被想当然写下的**。

| 当时的想法 | 被什么推翻 |
|---|---|
| 块加 `indexScope` 控制检索 | 「如果是为了检索，完全可以通过一个查询条件达到」 |
| 代码块默认不索引 | 「代码块也应该默认能查，只有用户显式配置才不支持」 |
| 用标签 `#no-index` 标识 | 自证三条硬伤：标签自己被索引／循环／公开声明矛盾 |
| 左槽用 `<nav id="pages">` 装页面 | 「我们的概念里一切皆块」 |
| 常驻图标入口条 | 堆叠让「替换」这个动作消失，入口条失去意义 |
| `props.role`／`_roles` 表达身份 | 地址与露面是两件事：地址在 `_aliases`（有序、首个主名），露面在 `_lists`（可兼位）；裸读由静态断言拦住 |
| `props` 的键写 `ns/kebab-name` | 键是**属性定义块的 id**：写名字就要在改名时迁移全库值；撞名靠 id 空间已经解决 |
| AI 隐私用块级标记 | 形态未定就设计接口 ＝ 过早抽象；且 AI 应当走查询通道 |
| 让 `tag`／`schema`／`journal` 住在任何块下面 | 位置对它们不承载信息（所有读路径按 id），却让所有树操作把它们当货物搬 ⇒ 删祖先带走标签、`journal` 被缩进后日记流看不见 |
| 给"必须顶层的块"做一张 `mustBeRoot` 名单 | 每加一种身份都要回答一次（＝名单），且只拦"是不是根"不拦"正在被移动" |
| 删子树时扫一遍、把必须顶层的块"提升"到顶层 | 把判断放回**出口**（删除是高频路径），每次删除都要遍历子树 |
| 给概念找临时替身，然后把替身当概念 | 「一组块」还没有载体时，命名容器块是个便宜的近似；但留着它，原型的临时形状就会被当成产品概念读，还占着一个露面值 |
| 在打字时逐字符校验标签重名 | 输入法中间态会撞名 ⇒ 打不进去 |

## 6 与「其它派系」的分歧点

这几处是**有意这么定**的，改之前请先看理由：

- **不引入 `Page` 实体**：多数实现有独立的 page 表／对象。我们用「块 ＋ 露面」，
  于是「页里可以有子页」「页就是块」这类能力是**免费**的。
- **正文不是 contenteditable 套富文本框架**：自研块级 DOM ＋ 块内 run 序列（原子不可分、
  格式随文字走），于是「跨块选择」「原地编辑」「一源多视」在模型层就成立。
- **不把折叠态写在块上**：那是「这一行此刻怎么显示」，它挂在文档／设备那一层
  （`Doc.folded`／`DeviceState.folded`），块自己只有内容。判据 ② 不是「不落盘」而是
  **不混进内容**——折叠一旦是块的字段，合并／复制／导出／撤销都会顺手搬它。
