# 路线图

> 这份只写**接下来做什么、按什么顺序**。已做成的能力在 [`../README.md`](../README.md)「现在能做什么」，
> 每条约束**为什么存在**在 [`ARCH-断言.md`](ARCH-断言.md) 与 [`模型-一切皆块.md`](模型-一切皆块.md)。

当前阶段：**原型**。目标是先把**输入面形状**与**三张表**钉死，再往真实存储上换。

---

## 0 判断优先级的两条尺子

排在做与不做之间的，不是「谁先想起来的」，而是这两条：

1. **它会不会让输入面的形状退化？** 会 ⇒ 最高优先级。
   （输入面形状 = 块树 ＋ 带 `blockId` 的区间锚点 ＋ IME 组合不出错）
2. **它是不是「一次换实现、上层不改」的接缝？** 是 ⇒ 值得提前铺，因为它决定后面所有能力长什么样。
   （例：持久化的 `StoragePort`、渲染的 `renderBlock`、命令的声明表）

反过来，**看起来紧急但可以后置**的：界面细节、皮肤、动画、导入导出格式、多端。

---

## 1 现在这一格：把「引用」变成一等公民

### 1.1 RefResolver —— 引用要跟着目标改名

**现状**：引用的 `label` 是插入时的快照，目标改名后引用还显示旧名。
**要做**：渲染时解析目标当前正文，`label` 降级为「目标不存在时的兜底」。
**验收**：改页名 ⇒ 所有引用立刻显示新名；目标被删 ⇒ 显示为 dangling 状态而不是错指。

### 1.2 标签＝引用边

**现状**：`#tag` 只是正文里的文本，所以**标签产生不了反链**。
**要做**：`insert-tag` / 渲染 / 索引统一走引用边，不留「正则解析」这第二套真相。
**验收**：给块打标签 ⇒ 标签页的反链里出现这个块；把标签文本删掉 ⇒ 边也随之消失（不留孤儿）。

### 1.3 IndexPort —— 反链不再全库扫

**现状**：每次算反链都扫全库，`rebuild` 与 `incremental` 没有一致性保证。
**要做**：定入向边 / 标签 / 搜索共用的索引契约；先写 `rebuild == incremental` 的测试骨架，再实现。
**验收**：同一批操作，先 rebuild 再与增量累积结果**逐字节一致**。

> 1.1 → 1.2 → 1.3 有依赖：先有「解析」，才谈得上「边的语义」，最后才谈得上「索引」。

## 2 下一格：换真实存储

### 2.1 Tx / Changes —— 写盘不再整库序列化

**现状**：`StoragePort` 已经异步 ＋ 批次，但**适配器内部仍是 `JSON.stringify(整库)`**。
⇒ 容量有限、卡顿、没有真正的事务。
**要做**：让 `commit(batch)` 收到的 `Change[]` 真的只含改过的那几块（现在是「整类对象都动过」）。
**验收**：改一个块 ⇒ 提交的 `Change[]` 里只有它；大库里打字不掉帧。

### 2.2 SQLite 适配器

**前置**：2.1 完成。端口不变，只换实现（`createWorkspaceStore(createSqliteAdapter(...))`）。
**那一刻**才叫「接数据库」。**renderer 一行不改**是本条的验收标准。

### 2.3 备份 / 导出

**现状**：读盘失败会进只读态（不覆盖），但用户**没有抢救手段**。
**要做**：至少一条「把当前库导出成文件」的出口。这是数据安全的下限，不该排在很后面。

## 3 输入面的未完成项

| 项 | 现状 | 要做 |
|---|---|---|
| **跨块编辑** | 块选区能选中，删除/替换没在模型侧实现 | 模型侧接受 `Selection[]` 作为 `Delete`/`Replace` 的操作对象 |
| **`⌘F` 自研查找** | 没有绑定（契约上留了位） | 落进「上下文键」而不是全局劫持 |
| **多行块（代码/SQL）** | 只有单行原子 | 独立编辑器实例，**不塞进同一个 contenteditable** |
| **虚拟化滚动联动** | 已窗口化挂载，但滚动与选区投影没有联动 | 见 `docs/ELECTRON-备忘.md` 里实测到的「组合期块被卸载」 |
| **Undo 粒度** | 全量快照，大库会重 | 改成按事务批的差量 |

## 4 壳与发布

- **签名与公证**（现在 `.app` 未签名，换机器会被 Gatekeeper 拦）
- **CSP 收紧**（现在 `default-src 'self'` 够用，但还没逐项审）
- **深色跟随系统**在真机上复核一次（当前环境测不出媒体查询的变化）
- **自动更新**（原型阶段不做，但要在做之前想清楚：它和「不签名」是互斥的）

---

## 5 明确**不做**（至少现在）

| 不做 | 为什么 |
|---|---|
| 换掉 Electron | 壳已经做到「主进程不含业务」，换壳收益低于成本 |
| 引入前端框架 | 编辑器 DOM 是自研的，引框架只会多一层需要对抗的抽象 |
| 皮肤 / 主题市场 | 主题只填 `--ui-*` 的机制已经在了，等真正有第三方需求再说 |
| 兼容旧落盘格式 | 原型阶段 `WORKSPACE_VERSION` 加一即作废，写迁移是纯负债 |
| 移动端 | 要等「事务 + 同步」落地之后；现在做只能做出一个分叉的模型 |
