# 路线图

> 这份只写**接下来做什么、按什么顺序**。已做成的能力在 [`../README.md`](../README.md)「现在能做什么」，
> 每条约束**为什么存在**在 [`ARCH-断言.md`](ARCH-断言.md) 与 [`模型-一切皆块.md`](模型-一切皆块.md)。

当前阶段：**原型**。目标是先把**输入面形状**与**三张表**钉死，再往真实存储上换。

---

## 0 判断优先级的两条尺子

排在做与不做之间的，不是「谁先想起来的」，而是这两条：

1. **它会不会让输入面的形状退化？** 会 ⇒ 最高优先级。
   （输入面形状 = 块树 ＋ 块内 run 序列 ＋ IME 组合不出错）
2. **它是不是「一次换实现、上层不改」的接缝？** 是 ⇒ 值得提前铺，因为它决定后面所有能力长什么样。
   （例：持久化的 `StoragePort`、渲染的 `renderBlock`、命令的声明表）

反过来，**看起来紧急但可以后置**的：界面细节、皮肤、动画、导入导出格式、多端。

## 1 现在这一格：把「引用」变成一等公民

### 1.1 RefResolver —— 引用要跟着目标改名 ✅ **已落地**

**现状**：~~引用的 `label` 是插入时的快照，目标改名后引用还显示旧名。~~
**已做**：`core/ref.ts` 的 `resolveRef(find, atom)` 在**渲染时**解析目标当前正文，
`label` 降级为「解析不到时的兜底」；`Atom.state` 落盘字段删掉（能不能解析到是派生的，不落盘）。
**验收**：改页名 ⇒ 所有引用立刻显示新名（且不回写原子）；目标被删 ⇒ 显示为 dangling 而不是错指。
（冒烟 `T39`，单测 `tests/ref.test.ts`。）

**已知残留**：解析走 `store.find` 遍历森林（每个引用 O(n)），大库下要等 1.3 的反向索引。

### 1.2 标签＝块上的一格分类 ✅ **已落地**

**现状**：~~`#tag` 只是正文里的文本，所以**标签产生不了反链**。~~
**已做**：标签＝一个 `_lists` 含 `tag` 的**块**（名字住在 `_aliases`，正文是描述），归属＝打标签那个块上的
`props._tags`（有序的标签块 id 列表），渲染成行尾 chip（不占正文）。
判据：**归属只有一份**（`props._tags`），写它的入口只有块级那一处。正文里敲 `#名` 是**提及**：
一枚占 1 格的引用 run（指向标签类或一条实例），敲下分隔符或回车才生效，**不写归属** ——
所以提及某个标签不会让这块成为它的成员，也不会长出它的字段。
两者唯一的重叠是显示：同一行里已经提过的标签不再重复画 chip。
**删字不摘标签**：删掉正文里那枚只是不再提它，归属仍在、chip 落回；摘标签是一次显式动作
（检视卡的「标签」一行可以挂/摘；摘时把正文里那枚一起收掉）。
**验收**：给块打标签 ⇒ 它出现在标签的成员列表里；成员是从块上的归属派生出来的。
（冒烟 `T40`／`T58`／`T58b`，单测 `tests/tags.test.ts`。）

**已知边界**：`#` 的**自动补全**（边打边提示已有标签）未做 —— 现在只有敲完才落成标签；
`cleanableValues` 的清理提示在「摘标签」入口接上后仍未回到面板（派生有单测）。
（字段声明与标签层级已落地，见 1.4。）

### 1.3 IndexPort —— 反链不再全库扫 ✅ **已落地**

**现状**：~~每次算反链都扫全库，`rebuild` 与 `incremental` 没有一致性保证。~~
**已做**：`core/index-port.ts` 的五张派生表（块 / 入向边 / 标签成员 / 名字与日期 / 归属页），
`BlockStore` 懒重建缓存；`find` 与反链改走查表，不再遍历森林。
**验收**：同一批操作，先 rebuild 再与增量累积结果**逐字节一致** —— 已兑现，
并覆盖四个增量失效点（文本编辑 / 原子增删 / 目标删除 / 块移动）。

**粒度说明**：变化通知目前只能报「整类对象都动过」，所以增量只能做到「没动的那一类不重建」。
按块粒度要等事务层产出具体的块 id；那时 `applyChanges` 的形状不变。

**顺带修掉的真 bug**：删页会直接改森林、再换视图，而「换视图」不发变更通知 ⇒
索引停在旧库上，**删掉的页仍能被查到**。现在两条旁路都显式作废索引。

> 1.1 → 1.2 → 1.3 有依赖：先有「解析」，才谈得上「边的语义」，最后才谈得上「索引」。
> **三条都已完成。**

### 1.4 标签 / 页 / 属性的统一 ✅ **已落地**

**已做**：**地址与露面分开**——名字住在 `props._aliases`（0..N，首个是主名，全局唯一，允许 `/` 分段、
显示叶子），正文（`content` 的文本投影）是描述；页/标签是 `props._lists` 里的两个**露面**（可兼位、可空，顺序无语义，
判定只走 `hasList` 家族）· 行头的**别名编辑器**（加/删名字、设主名、勾页/标签列表、切换显示别名或文本）·
页与标签共用**地址空间**（`_aliases` ＋ 一处归一化，`# 设计 `／`#设计`／`[[设计]]` 同一块）·
字段定义是**独立块**（有 `_kind` 的块，住森林顶层，`propId` ＝ 块 id）· 值在块上 `props[propId]`（一块一槽）·
属性平铺 ＋ 来源标注（同一 `propId` 只一行；画在**右槽的检视卡**上，跟着当前对象走）· 摘标签提示清理（默认保留，可撤销）·
标签层级（属于/包含，一条边两个读法；成员**算作**、**字段不继承**；写入禁环；删父留可见悬空）。

**验收**：`tests/alias.test.ts` · `tests/lists.test.ts` · `tests/props.test.ts` · `tests/tag-tree.test.ts`；
冒烟 `T39`（显示名与改名）· `T51`（属性区）· `T52`（层级与算作）· `T53`（列表露面）。

**已知边界**：`ref` 值的专用选择器、choices 目录编辑、字段定义列表视图（按露面筛选）后置。

## 2 下一格：换真实存储

### 2.1 Tx / Changes —— ~~写盘不再整库序列化~~（桌面版已落地）

**现状**：桌面版已经不是整库序列化了 —— 每个库一份 `qua.db`，块是**自己的行**
（`Block`／`BlockProperty`／`BlockAlias`／`BlockList`），一次编辑只写它动过的那几块。
**验收**：`tests/storage/db-rows.test.ts`（小库与大库的落盘行数必须相同）＋
`checks/electron-smoke.mjs` 的 E12（真 Electron 里数行）。
**还剩**：浏览器端仍是整份字节（浏览器没有库目录的同等语义）；`Change[]` 仍可能报「整类都动过」
（那是「确实不知道」的如实表达，不是漏做）。

### 2.2 SQLite 适配器 —— ~~已完成~~（桌面版就是它）

端口不变、只换实现已经做到：`createWorkspaceStore(createIpcAdapter(...))`，**renderer 的业务代码一行没改**。
**还剩**：装载仍是整份读（运行模型是「整片森林在内存」）；按 id／按页的局部装载要等查询与反链也走 SQL。

### 2.3 备份 / 导出

**现状**：读盘失败会进只读态（不覆盖）；开发构建的调试菜单已有「备份并重建本地库」——
原始字节先抄到 `qua.workspace.bak.<时刻>`，备份失败就中止覆盖。
**还缺**：用户面的「把当前库导出成文件」出口。这是数据安全的下限，不该排在很后面。

## 3 输入面的未完成项

| 项 | 现状 | 要做 |
|---|---|---|
| **跨块编辑** | 块选区能选中，删除/替换没在模型侧实现 | 模型侧接受 `Selection[]` 作为 `Delete`/`Replace` 的操作对象 |

| **虚拟化滚动联动** | 已窗口化挂载，但滚动与选区投影没有联动 | 见 `docs/ELECTRON-备忘.md` 里实测到的「组合期块被卸载」 |
| **Undo 粒度** | 全量快照，大库会重 | 改成按事务批的差量 |

## 4 壳与发布

- **签名与公证**（现在 `.app` 未签名，换机器会被 Gatekeeper 拦）
- **CSP 收紧**（现在 `default-src 'self'` 够用，但还没逐项审）

## 5 明确**不做**（至少现在）

| 不做 | 为什么 |
|---|---|
| 换掉 Electron | 壳已经做到「主进程不含业务」，换壳收益低于成本 |
| 引入前端框架 | 编辑器 DOM 是自研的，引框架只会多一层需要对抗的抽象 |
| 皮肤 / 主题市场 | 主题只填 `--ui-*` 的机制已经在了，等真正有第三方需求再说 |
| 兼容旧落盘格式 | 原型阶段 `WORKSPACE_VERSION` 加一即作废，写迁移是纯负债 |
| 移动端 | 要等「事务 + 同步」落地之后；现在做只能做出一个分叉的模型 |
